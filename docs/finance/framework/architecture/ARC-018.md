# ARC-018 — Architecture Multi-Cloud et Hybrid Cloud

> **Objectif :** Définir l'architecture Multi-Cloud et Hybrid Cloud d'EduWeb Planner afin d'assurer une disponibilité maximale, une souveraineté des données, une optimisation des coûts et une résilience adaptée aux déploiements nationaux et internationaux.

# 1. Vision

EduWeb Planner est destiné à être déployé :

- dans plusieurs établissements ;
- dans plusieurs académies ;
- dans plusieurs ministères ;
- dans plusieurs pays.

L'architecture ne doit donc dépendre d'aucun fournisseur de cloud unique.

Le choix d'une architecture **Multi-Cloud** et **Hybrid Cloud** garantit :

- une meilleure disponibilité ;
- une indépendance technologique ;
- une conformité réglementaire selon les pays ;
- une optimisation des coûts.

---

# 2. Objectifs

Cette architecture vise à :

- éviter le verrouillage fournisseur (*Vendor Lock-In*) ;
- améliorer la résilience ;
- rapprocher les services des utilisateurs ;
- respecter les exigences de souveraineté numérique ;
- répartir intelligemment les charges de travail.

---

# 3. Principes

Les principes directeurs sont :

- Cloud Agnostic
- Portabilité
- Haute disponibilité
- Résilience géographique
- Infrastructure as Code
- Sécurité unifiée
- Observabilité centralisée

---

# 4. Pourquoi une architecture Multi-Cloud ?

Une stratégie Multi-Cloud permet notamment :

- d'utiliser plusieurs fournisseurs selon leurs points forts ;
- de réduire les risques de panne globale ;
- de répondre aux exigences locales d'hébergement des données ;
- de négocier les coûts plus efficacement.

Cette approche est particulièrement adaptée aux plateformes nationales de gestion de l'éducation.

# 6. Cloud Public

Les fournisseurs compatibles comprennent :

- Amazon Web Services (AWS) ;
- Microsoft Azure ;
- Google Cloud Platform ;
- OVHcloud ;
- Oracle Cloud Infrastructure.

Le cloud public est privilégié pour :

- les applications Web ;
- les services IA ;
- les traitements analytiques ;
- les services à forte variabilité de charge.

---

# 7. Cloud Privé

Le cloud privé peut être déployé sur :

- OpenStack ;
- VMware ;
- Proxmox VE ;
- Nutanix.

Il héberge préférentiellement :

- les données sensibles ;
- les référentiels nationaux ;
- les systèmes ministériels ;
- les applications soumises à des exigences de souveraineté.

---

# 8. Cloud Hybride

L'architecture hybride combine les avantages des deux modèles.

Exemple :

| Composant | Hébergement recommandé |
|------------|------------------------|
| Authentification | Cloud privé |
| Référentiels nationaux | Cloud privé |
| IA | Cloud public |
| Portail Web | Cloud public |
| Sauvegardes | Double hébergement |
| Supervision | Répartie sur plusieurs sites |

Cette approche permet d'optimiser les performances tout en respectant les contraintes réglementaires.

---

# 9. Répartition des charges

Les services sont distribués selon plusieurs critères :

- proximité géographique ;
- disponibilité ;
- coût d'exploitation ;
- capacité des infrastructures ;
- contraintes réglementaires.

Le routage peut être basé sur :

- le pays ;
- la région ;
- la latence ;
- la charge ;
- la disponibilité.

---

# 10. Gestion des données

Les données sont réparties selon leur criticité.

### Données locales

- informations des établissements ;
- configurations spécifiques.

### Données nationales

- référentiels ;
- statistiques nationales.

### Données globales

- catalogue des services ;
- modèles IA ;
- documentation.

La réplication entre clouds est chiffrée et supervisée.

---

# 11. Continuité d'activité

L'architecture prévoit :

- plusieurs zones de disponibilité ;
- plusieurs régions cloud ;
- réplication des bases de données ;
- bascule automatique en cas d'incident (*Failover*) ;
- restauration rapide (*Failback*).

Les tests de reprise sont réalisés périodiquement.

---

# 12. Sécurité

Les mesures de sécurité comprennent :

- VPN inter-cloud ;
- chiffrement TLS 1.3 ;
- gestion centralisée des identités ;
- contrôle RBAC ;
- segmentation réseau ;
- journalisation centralisée.

Les secrets sont gérés dans un coffre-fort sécurisé (Vault ou équivalent).

---

# 13. Gouvernance

Un comité d'architecture définit :

- les fournisseurs autorisés ;
- les critères de sélection ;
- les règles de migration ;
- les politiques de sauvegarde ;
- les exigences de conformité.

Chaque nouveau service fait l'objet d'une analyse avant son déploiement.

---

# 14. FinOps

L'architecture intègre une démarche FinOps visant à :

- suivre les coûts par environnement ;
- optimiser les ressources consommées ;
- automatiser l'extinction des ressources inutilisées ;
- produire des rapports de consommation.

Des indicateurs sont suivis :

- coût par utilisateur ;
- coût par établissement ;
- coût par pays ;
- coût par microservice.

# Conclusion

L'architecture Multi-Cloud et Hybrid Cloud d'EduWeb Planner offre une infrastructure distribuée, résiliente et indépendante des fournisseurs. Elle répond aux enjeux de souveraineté numérique, de continuité de service et de maîtrise des coûts, tout en préparant la plateforme à un déploiement progressif à l'échelle des établissements, des ministères et des pays partenaires. Cette approche constitue un levier stratégique pour accompagner l'expansion internationale de l'écosystème EduWeb.
