# ARC-013 — Architecture de Sécurité

> **Objectif :** Définir l'architecture globale de sécurité d'EduWeb Planner afin de protéger les données, les utilisateurs, les infrastructures et les services contre les menaces internes et externes.

# 1. Vision

La sécurité est une responsabilité partagée.

Elle est intégrée dès la conception ("Security by Design") et ne constitue jamais une étape ajoutée en fin de développement.

L'objectif est de protéger :

- les données des élèves ;
- les informations administratives ;
- les emplois du temps ;
- les services numériques ;
- les infrastructures cloud.

---

# 2. Objectifs

L'architecture de sécurité doit permettre :

- garantir la confidentialité ;
- assurer l'intégrité ;
- maintenir la disponibilité ;
- assurer la traçabilité ;
- limiter les impacts des incidents.

---

# 3. Principes

Les principes retenus sont :

- Zero Trust
- Least Privilege
- Defense in Depth
- Security by Design
- Privacy by Design
- Secure by Default
- Audit by Default

# 6. Gestion des identités

L'authentification repose sur :

- OAuth2
- OpenID Connect
- JWT
- MFA

Les autorisations utilisent :

- RBAC
- ABAC

Les comptes privilégiés font l'objet d'une surveillance renforcée.

---

# 7. Protection des données

Les données sont classées selon leur sensibilité :

| Niveau | Exemple |
|---------|----------|
| Public | Informations institutionnelles |
| Interne | Référentiels |
| Confidentiel | Données pédagogiques |
| Très sensible | Données personnelles, authentification |

Mesures :

- chiffrement AES-256 au repos ;
- TLS 1.3 en transit ;
- rotation des clés ;
- masquage des données sensibles.

---

# 8. Sécurité réseau

Les communications sont protégées par :

- HTTPS obligatoire ;
- segmentation réseau ;
- VPN pour l'administration ;
- listes de contrôle d'accès (ACL).

Les ports inutiles sont fermés.

---

# 9. Sécurité applicative

Les applications respectent les recommandations OWASP.

Contrôles :

- validation des entrées ;
- protection XSS ;
- protection CSRF ;
- protection contre les injections SQL ;
- limitation de débit ;
- gestion sécurisée des sessions.

Les dépendances sont analysées régulièrement pour détecter les vulnérabilités.

---

# 10. Journalisation et audit

Les événements suivants sont enregistrés :

- authentifications ;
- modifications des données ;
- changements de rôles ;
- accès aux informations sensibles ;
- erreurs de sécurité.

Les journaux sont centralisés et horodatés.

---

# 11. Détection des incidents

Les événements de sécurité sont surveillés en continu.

Exemples :

- tentatives de connexion répétées ;
- élévation de privilèges ;
- activité inhabituelle ;
- accès hors horaires ;
- trafic anormal.

Des alertes sont transmises aux administrateurs.

---

# 12. Gestion des vulnérabilités

Une politique de gestion des vulnérabilités comprend :

- scans automatisés ;
- tests d'intrusion ;
- revue de code ;
- mise à jour des dépendances ;
- correctifs de sécurité.

Les vulnérabilités critiques sont corrigées en priorité.

---

# 13. Conformité

L'architecture vise la conformité avec :

- ISO/IEC 27001 ;
- ISO/IEC 27002 ;
- OWASP ASVS ;
- NIST Cybersecurity Framework ;
- réglementations nationales relatives à la protection des données.

---

# Conclusion

L'architecture de sécurité d'EduWeb Planner constitue un cadre global assurant la protection des actifs numériques, des données éducatives et des utilisateurs. En combinant des mécanismes de prévention, de détection et de réaction, elle garantit une plateforme robuste, conforme aux bonnes pratiques internationales et capable d'évoluer face aux nouvelles menaces.
