# ARC-010 — Architecture des données

> **Objectif :** Définir l'architecture de gestion des données d'EduWeb Planner afin de garantir leur cohérence, leur qualité, leur sécurité et leur valorisation tout au long de leur cycle de vie.

# 1. Vision

Les données constituent le patrimoine numérique d'EduWeb Planner.

Elles doivent être :

- fiables ;
- cohérentes ;
- sécurisées ;
- historisées ;
- partageables ;
- exploitables pour la décision.

L'architecture des données est conçue pour accompagner plusieurs pays et plusieurs ministères tout en garantissant l'indépendance des établissements.

---

# 2. Principes

Les principes directeurs sont :

- **Single Source of Truth**
- **Data First**
- **Database per Domain**
- **Master Data Management**
- **Data Quality by Design**
- **Privacy by Design**
- **Audit by Default**

# 7. Gouvernance des données

Chaque domaine possède un **Data Owner**.

| Domaine | Responsable |
|----------|-------------|
| Établissements | Direction administrative |
| Enseignants | Ressources humaines |
| Élèves | Vie scolaire |
| Emplois du temps | Censeur |
| Examens | Service pédagogique |

Les responsabilités incluent :

- validation ;
- qualité ;
- sécurité ;
- conformité.

---

# 8. Qualité des données

Les contrôles suivants sont appliqués :

- unicité des identifiants ;
- validation des formats ;
- contrôle des doublons ;
- validation des références ;
- contrôle des dates ;
- cohérence métier.

Exemple :

Un enseignant ne peut être affecté qu'à un établissement actif.

---

# 9. Sécurité des données

Les mesures de protection comprennent :

- chiffrement des données sensibles ;
- chiffrement TLS des communications ;
- contrôle d'accès RBAC ;
- masquage des données sensibles ;
- journalisation des accès.

Les informations personnelles sont traitées conformément aux réglementations applicables.

---

# 10. Sauvegardes

Politique recommandée :

- sauvegarde incrémentielle horaire ;
- sauvegarde complète quotidienne ;
- réplication continue des journaux (WAL) ;
- restauration testée mensuellement.

---

# 11. Référentiels nationaux

EduWeb Planner doit pouvoir intégrer les référentiels officiels :

- établissements ;
- enseignants ;
- régions administratives ;
- structures pédagogiques ;
- nomenclatures ministérielles.

Ces référentiels sont synchronisés via API ou import sécurisé.

---

# 12. Architecture analytique

Les données opérationnelles alimentent un entrepôt décisionnel.

```text
Applications

↓

PostgreSQL

↓

ETL / ELT

↓

Data Warehouse

↓

Power BI / Grafana / IA
```

Les tableaux de bord ne doivent pas interroger directement les bases transactionnelles.

---

# 13. Performance

Objectifs :

| Indicateur | Cible |
|------------|------:|
| Temps de réponse des requêtes courantes | < 300 ms |
| Génération d'un tableau de bord | < 5 s |
| Synchronisation des référentiels | < 10 min |
| Disponibilité des données | ≥ 99,9 % |

Des index, partitions et mécanismes de cache (Redis) sont utilisés pour maintenir les performances.

# Conclusion

L'architecture des données d'EduWeb Planner garantit une gestion fiable, sécurisée et évolutive de l'information. Elle fournit un socle robuste pour les opérations quotidiennes des établissements, les analyses décisionnelles et les futurs services d'intelligence artificielle, tout en assurant la cohérence des référentiels éducatifs à l'échelle nationale et internationale.
