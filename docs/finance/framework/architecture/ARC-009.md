# ARC-009 — Architecture de gestion des identités et des accès (IAM)

> **Objectif :** Définir l'architecture de gestion des identités, de l'authentification, de l'autorisation et du contrôle des accès afin de garantir la sécurité des utilisateurs et des ressources d'EduWeb Planner.

# 1. Vision

EduWeb Planner est une plateforme **multi-pays**, **multi-ministères** et **multi-établissements**.

L'architecture IAM doit permettre à un utilisateur de disposer d'une identité unique tout en pouvant exercer plusieurs fonctions dans plusieurs établissements, sans compromettre la sécurité.

---

# 2. Principes

Les principes fondamentaux sont :

- Identity First
- Zero Trust
- Least Privilege
- Separation of Duties
- Multi-Tenant Security
- Traçabilité complète
- Authentification forte

# 5. Authentification

Méthodes supportées :

- Nom d'utilisateur / mot de passe
- E-mail
- Téléphone
- OTP SMS
- OTP E-mail
- Authenticator (TOTP)
- Passkeys
- OAuth2
- OpenID Connect
- LDAP
- Active Directory
- FranceConnect / équivalent national (si disponible)

---

## Authentification multifactorielle (MFA)

Obligatoire pour :

- administrateurs ;
- responsables régionaux ;
- direction générale ;
- comptes techniques.

# 6. Gestion des rôles

Le modèle repose sur le **RBAC** (Role-Based Access Control).

Exemple :

```text
Administrateur National

↓

Administrateur Régional

↓

Chef d'établissement

↓

Censeur

↓

Enseignant

↓

Élève

↓

Parent
```

Chaque rôle possède un ensemble de permissions.

---

# 7. Contrôle des accès

Les autorisations reposent sur plusieurs critères.

## RBAC

Accès selon le rôle.

---

## ABAC

Accès selon des attributs :

- établissement ;
- région ;
- pays ;
- discipline ;
- année scolaire.

---

## Exemple

Un enseignant :

✔ consulte ses classes.

✔ modifie ses disponibilités.

✖ ne modifie pas les emplois du temps d'un autre établissement.

# 9. Fédération d'identités

L'architecture permet :

- Single Sign-On (SSO)
- Authentification fédérée
- Connexion via plusieurs fournisseurs d'identité

Exemples :

- Google Workspace
- Microsoft Entra ID
- LDAP académique
- Annuaire ministériel

---

# 10. Journalisation

Les événements suivants sont enregistrés :

- connexion ;
- déconnexion ;
- changement de mot de passe ;
- activation MFA ;
- création d'un compte ;
- changement de rôle ;
- élévation de privilèges ;
- échec d'authentification.

Les journaux sont centralisés dans le système d'audit.

---

# 11. Sécurité

Les mesures suivantes sont obligatoires :

- TLS 1.3 ;
- chiffrement des mots de passe (Argon2id ou bcrypt) ;
- rotation des secrets ;
- verrouillage après plusieurs échecs ;
- détection d'anomalies ;
- expiration des sessions ;
- révocation des jetons.

Les mots de passe ne sont jamais stockés en clair.

---

# 12. Gouvernance

Chaque identité possède :

- un propriétaire ;
- un responsable métier ;
- une date de création ;
- un historique des modifications ;
- un niveau de sensibilité.

Une revue des droits d'accès est effectuée au minimum une fois par semestre.

---

# 13. Checklist

- □ Authentification centralisée
- □ MFA activé pour les comptes sensibles
- □ RBAC configuré
- □ ABAC documenté
- □ Journalisation activée
- □ SSO opérationnel
- □ Révocation des accès automatisée
- □ Comptes inactifs désactivés
- □ Revue périodique des droits réalisée
- □ Politique IAM validée

# Conclusion

L'architecture IAM d'EduWeb Planner constitue le socle de confiance de la plateforme. Elle garantit une gestion centralisée des identités, une authentification sécurisée, un contrôle d'accès granulaire et une traçabilité complète, indispensables à un système éducatif multi-tenant déployé à l'échelle nationale ou panafricaine.
