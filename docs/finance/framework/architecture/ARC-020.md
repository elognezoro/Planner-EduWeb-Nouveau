# 1. Vision stratégique

EduWeb Planner ambitionne de devenir la **plateforme numérique de référence pour la gestion des établissements d'enseignement en Afrique francophone**, extensible à d'autres espaces linguistiques.

L'architecture cible répond simultanément aux besoins :

- des établissements scolaires ;
- des établissements techniques et professionnels ;
- des universités ;
- des académies et inspections ;
- des ministères ;
- des partenaires internationaux.

Elle est conçue pour accueillir **plusieurs millions d'utilisateurs**, tout en restant modulaire, sécurisée et évolutive.

---

# 2. Principes directeurs

L'architecture cible repose sur les principes suivants :

- Business Driven Architecture
- Cloud Native
- API First
- Event Driven
- Data Centric
- AI Native
- Zero Trust
- Multi-Tenant by Design
- Open Standards
- Sustainable Architecture

---

# 3. Objectifs de transformation

À l'horizon 2035, EduWeb Planner devra permettre :

- une gestion entièrement numérique des établissements ;
- une planification automatisée par IA ;
- une gouvernance nationale des données éducatives ;
- une intégration fluide avec les systèmes ministériels ;
- une exploitation multi-pays ;
- une disponibilité continue des services.

# 5. Les couches de l'architecture

L'architecture est organisée en six couches complémentaires.

## 5.1 Couche métier

Elle regroupe les processus de :

- planification ;
- gestion administrative ;
- vie scolaire ;
- évaluations ;
- pilotage.

---

## 5.2 Couche applicative

Elle est composée de microservices spécialisés couvrant :

- l'identité ;
- les établissements ;
- les enseignants ;
- les élèves ;
- les salles ;
- les emplois du temps ;
- les examens ;
- les notifications ;
- les rapports ;
- l'intelligence artificielle.

---

## 5.3 Couche données

Elle centralise :

- les données opérationnelles ;
- les référentiels nationaux ;
- les données analytiques ;
- les modèles IA ;
- les journaux d'audit.

---

## 5.4 Couche technologique

Elle comprend :

- Kubernetes ;
- PostgreSQL ;
- Redis ;
- MinIO ;
- API Gateway ;
- Message Broker ;
- Observabilité.

---

## 5.5 Couche sécurité

Elle garantit :

- authentification ;
- autorisation ;
- chiffrement ;
- audit ;
- conformité.

---

## 5.6 Couche exploitation

Elle regroupe :

- supervision ;
- CI/CD ;
- sauvegardes ;
- PRA ;
- FinOps ;
- SRE.

# 6. Capacités métier

Les capacités sont organisées en domaines.

| Domaine | Capacités principales |
|----------|-----------------------|
| Gouvernance | Administration, référentiels |
| Planification | Génération des emplois du temps |
| Ressources humaines | Gestion des enseignants |
| Vie scolaire | Élèves, classes, absences |
| Évaluation | Examens, notes, statistiques |
| Pilotage | KPI, tableaux de bord |
| IA | Optimisation, recommandations |

---

# 7. Architecture applicative

Les applications de l'écosystème EduWeb comprennent notamment :

- **EduWeb Planner** : gestion des emplois du temps et des établissements ;
- **EduWeb Governance** : gestion administrative et réglementaire ;
- **EduWeb Family** : relation entre familles et professionnels de l'éducation ;
- **EduWeb Booking** : réservation des ressources ;
- **E-School EduWeb** : plateforme d'apprentissage numérique.

Chaque application expose des API et peut évoluer indépendamment.

---

# 8. Architecture des données

Les données sont organisées autour de référentiels partagés et de bases spécialisées.

Principes :

- une source de vérité par domaine ;
- historique complet des modifications ;
- synchronisation contrôlée ;
- qualité des données mesurée en continu.

---

La plateforme repose sur les technologies suivantes :

| Domaine | Technologies de référence |
|----------|---------------------------|
| Frontend | React, Next.js |
| Backend | Node.js, NestJS |
| Base de données | PostgreSQL |
| Cache | Redis |
| Stockage objet | MinIO |
| Orchestration | Kubernetes |
| Conteneurisation | Docker |
| API | REST, GraphQL, gRPC |
| Observabilité | Prometheus, Grafana, Loki, Jaeger |
| IA | LLM, RAG, Vector Store |

Les choix technologiques pourront évoluer sans remettre en cause les principes d'architecture.

# 10. Architecture IA

L'IA intervient dans :

- la génération des emplois du temps ;
- la recommandation pédagogique ;
- la prévision des effectifs ;
- la détection d'anomalies ;
- l'assistance conversationnelle ;
- la production de rapports.

Les décisions critiques restent sous validation humaine.

---

# 11. Architecture de sécurité

La sécurité repose sur :

- Zero Trust ;
- MFA ;
- RBAC/ABAC ;
- chiffrement ;
- journalisation ;
- surveillance continue ;
- audits réguliers.

Les exigences sont détaillées dans les documents ARC-009 et ARC-013.

# 12. Architecture d'exploitation

L'exploitation est organisée autour de :

- GitOps ;
- CI/CD ;
- supervision temps réel ;
- sauvegardes automatisées ;
- PRA/PCA ;
- pratiques SRE.

# 14. Maturité de l'architecture

L'évolution est prévue selon cinq niveaux.

| Niveau | Caractéristiques |
|---------|------------------|
| 1 | Architecture initiale |
| 2 | Microservices |
| 3 | Cloud Native |
| 4 | IA intégrée |
| 5 | Écosystème multi-pays intelligent |

Chaque niveau est associé à des critères de gouvernance et d'exploitation.

---

# 15. Gouvernance

La gouvernance de l'architecture repose sur :

- un **Architecture Review Board** ;
- des **Architecture Decision Records (ADR)** ;
- des standards techniques ;
- des revues de conformité ;
- une gestion des dérogations.

Toute évolution majeure est évaluée avant sa mise en production.

---

# 16. Feuille de route

## Court terme (1 à 2 ans)

- finalisation de l'architecture microservices ;
- déploiement Kubernetes ;
- automatisation CI/CD.

### Moyen terme (3 à 5 ans)

- généralisation de l'IA ;
- architecture multi-cloud ;
- portail national.

### Long terme (5 à 10 ans)

- fédération de plusieurs pays ;
- analyses prédictives avancées ;
- assistants IA spécialisés ;
- intégration complète avec les systèmes éducatifs nationaux.

# 18. Synthèse

L'architecture cible d'EduWeb Planner fournit une vision cohérente de l'ensemble des capacités métier, des applications, des données, des technologies et des mécanismes de gouvernance. Elle constitue le référentiel directeur guidant les décisions d'investissement, de développement et d'exploitation, tout en garantissant la cohérence des évolutions futures.

L'architecture cible d'EduWeb Planner constitue la vision directrice de l'ensemble de l'écosystème numérique EduWeb. En intégrant les meilleures pratiques d'architecture d'entreprise (TOGAF), de sécurité (Zero Trust), d'exploitation (SRE), d'ingénierie logicielle (DevSecOps), de gestion des données et d'intelligence artificielle, elle fournit un cadre robuste, évolutif et durable pour accompagner la transformation numérique des systèmes éducatifs à l'échelle nationale, régionale et internationale.
