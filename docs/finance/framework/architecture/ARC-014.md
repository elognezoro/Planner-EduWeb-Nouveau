# ARC-014 — Architecture DevSecOps

> **Objectif :** Définir l'architecture DevSecOps d'EduWeb Planner afin d'automatiser le développement, les tests, la sécurité et le déploiement des applications tout en garantissant qualité, rapidité et conformité.

# 1. Vision

Le développement d'EduWeb Planner repose sur une approche **DevSecOps**, où les équipes Développement, Sécurité et Exploitation collaborent autour d'une chaîne d'automatisation unique.

La sécurité n'est plus une étape finale : elle est intégrée dès les premières phases de conception.

---

# 2. Objectifs

L'architecture DevSecOps vise à :

- accélérer les livraisons ;
- améliorer la qualité du code ;
- automatiser les tests ;
- intégrer les contrôles de sécurité ;
- réduire les erreurs humaines ;
- garantir des déploiements reproductibles.

---

# 3. Principes

Les principes fondamentaux sont :

- Automation First
- Everything as Code
- Security by Design
- Continuous Testing
- Continuous Delivery
- Continuous Monitoring
- Continuous Improvement

# 5. Gestion du code source

Le code est hébergé dans un dépôt Git.

Convention de branches :

```text
main

develop

feature/*

release/*

hotfix/*
```

Chaque modification est réalisée via **Pull Request**.

Une revue de code est obligatoire avant fusion.

---

# 6. Intégration Continue (CI)

Chaque commit déclenche automatiquement :

- compilation ;
- tests unitaires ;
- analyse statique ;
- contrôle du style ;
- génération de la documentation ;
- analyse des dépendances ;
- scan de sécurité.

Aucune fusion n'est autorisée si une étape échoue.

---

# 7. Livraison Continue (CD)

Pipeline type :

```text
Build

↓

Tests

↓

Image Docker

↓

Registry

↓

Déploiement DEV

↓

Validation

↓

Déploiement TEST

↓

Validation

↓

Préproduction

↓

Production
```

Les mises en production utilisent des **Rolling Updates**.

# 9. Gestion des environnements

Environnements recommandés :

| Environnement | Objectif |
|---------------|----------|
| Local | Développement |
| Dev | Intégration |
| Test | Validation |
| Préproduction | Recette |
| Production | Exploitation |

Chaque environnement possède :

- sa configuration ;
- ses secrets ;
- ses bases de données ;
- ses pipelines.

---

# 10. Observabilité

Les pipelines publient automatiquement :

- rapports de tests ;
- couverture de code ;
- qualité logicielle ;
- vulnérabilités ;
- métriques de déploiement.

Outils recommandés :

- GitHub Actions ou GitLab CI ;
- SonarQube ;
- Trivy ;
- OWASP Dependency Check ;
- Prometheus ;
- Grafana ;
- Loki ;
- Jaeger.

---

# 11. Gouvernance

Chaque pipeline est versionné.

Les règles suivantes sont obligatoires :

- revue de code ;
- approbation des mises en production ;
- journalisation des déploiements ;
- traçabilité des versions ;
- archivage des artefacts.

Les changements majeurs sont validés par l'Architecture Board.
