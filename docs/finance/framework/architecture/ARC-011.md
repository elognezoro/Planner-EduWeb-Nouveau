# ARC-011 — Architecture décisionnelle et Analytics

> **Objectif :** Définir l'architecture décisionnelle d'EduWeb Planner afin de transformer les données opérationnelles en informations exploitables pour le pilotage des établissements, des inspections, des DRENA et des ministères.

# 1. Vision

Les données produites quotidiennement par EduWeb Planner constituent un patrimoine stratégique.

L'objectif est de transformer ces données en informations décisionnelles afin de permettre :

- le pilotage des établissements ;
- le suivi des performances ;
- l'optimisation pédagogique ;
- l'aide à la décision.

---

# 2. Objectifs

L'architecture décisionnelle permet de :

- consolider les données ;
- produire des indicateurs fiables ;
- automatiser les rapports ;
- alimenter les moteurs d'IA ;
- détecter les anomalies.

---

# 3. Principes

- Single Source of Truth
- Near Real-Time Analytics
- Self-Service BI
- Data Governance
- Explainable Analytics

# 5. Sources de données

Les principales sources sont :

- établissements ;
- enseignants ;
- élèves ;
- emplois du temps ;
- examens ;
- absences ;
- paiements ;
- notifications ;
- audit.

---

# 6. Data Warehouse

Le Data Warehouse centralise les données historisées.

Il est organisé selon un modèle en étoile :

- Dimensions :
  - Temps
  - Établissement
  - Enseignant
  - Classe
  - Salle
  - Discipline

- Faits :
  - Séances
  - Examens
  - Absences
  - Inscriptions

---

# 7. Data Marts

Des Data Marts spécialisés sont créés pour :

- Ministère ;
- DRENA ;
- Inspection ;
- Établissements ;
- Direction générale EduWeb.

---

# 8. Tableaux de bord

Exemples :

## National

- nombre d'établissements ;
- taux de couverture ;
- taux d'utilisation.

## Régional

- emplois du temps publiés ;
- établissements actifs ;
- enseignants.

## Établissement

- occupation des salles ;
- conflits détectés ;
- heures enseignées ;
- absences.

---

# 9. Intelligence artificielle

Les données alimentent :

- prévisions d'effectifs ;
- recommandations ;
- détection d'anomalies ;
- optimisation des emplois du temps ;
- maintenance prédictive.

---

# 10. Sécurité

- anonymisation ;
- pseudonymisation ;
- contrôle RBAC ;
- chiffrement ;
- journalisation.

---

# 11. Performance

Objectifs :

- tableaux de bord < 5 s ;
- rapports < 30 s ;
- actualisation quotidienne ou temps réel selon les usages.

---

# 12. Gouvernance

Chaque indicateur possède :

- un propriétaire ;
- une définition officielle ;
- une fréquence de calcul ;
- une source.

---

# 13. KPI

Exemples :

- taux d'occupation des salles ;
- taux de conflits résolus ;
- disponibilité des enseignants ;
- couverture des emplois du temps ;
- délai moyen de génération ;
- taux d'utilisation de la plateforme.

---

# 14. Checklist

- □ Data Warehouse opérationnel
- □ KPI validés
- □ Data Marts créés
- □ Dashboards publiés
- □ Sécurité appliquée
- □ Gouvernance documentée
