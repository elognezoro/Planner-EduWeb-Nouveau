# OPS-010 — Plan de Reprise d’Activité (Disaster Recovery Plan — DRP)

> **Objectif :** Définir le cadre de reprise d’activité d’EduWeb afin de restaurer les infrastructures, les applications, les données et les services critiques après un sinistre majeur, tout en garantissant la disponibilité, l’intégrité des informations et la continuité des missions essentielles.

# 1. Introduction

Même avec une excellente stratégie de continuité d’activité, un sinistre majeur peut rendre indisponibles :

- un centre informatique ;
- une plateforme Cloud ;
- une base de données ;
- un stockage ;
- un réseau ;
- un service critique.

Le **Plan de Reprise d’Activité (PRA)** définit les moyens permettant de restaurer les systèmes dans un délai compatible avec les exigences métier.

Le PRA intervient lorsque :

- la continuité ne suffit plus ;
- un sinistre est confirmé ;
- une restauration technique devient indispensable.

---

# 2. Vision

EduWeb adopte un PRA :

- automatisé autant que possible ;
- fondé sur la résilience ;
- géographiquement distribué ;
- testé régulièrement ;
- documenté ;
- intégré au BCP ;
- piloté par les risques ;
- compatible avec les architectures Cloud et hybrides.

L'objectif est de restaurer rapidement les services essentiels tout en limitant les pertes de données.

---

# 3. Objectifs

Le PRA poursuit les objectifs suivants :

- restaurer rapidement les infrastructures ;
- rétablir les applications critiques ;
- protéger les données ;
- limiter les pertes ;
- garantir l'intégrité ;
- assurer la traçabilité ;
- coordonner les équipes ;
- réduire le temps d'interruption ;
- respecter les RTO et RPO ;
- améliorer la résilience.

---

# 4. Principes directeurs

Le PRA repose sur les principes suivants :

- Recovery by Design
- Automation First
- Backup Before Recovery
- Integrity Before Availability
- Tested Recovery
- Geographic Redundancy
- Infrastructure as Code
- Immutable Recovery
- Secure Restoration
- Continuous Improvement
- Full Traceability

# 6. Concepts fondamentaux

## 6.1 Sinistre

Événement provoquant une indisponibilité majeure nécessitant une restauration.

---

## 6.2 Site principal

Site utilisé pour la production normale.

---

## 6.3 Site secondaire

Infrastructure destinée à accueillir temporairement la production.

---

## 6.4 RTO (Recovery Time Objective)

Temps maximal acceptable avant restauration du service.

---

## 6.5 RPO (Recovery Point Objective)

Perte maximale de données acceptable.

---

## 6.6 Bascule (Failover)

Transfert de l’exploitation vers un site ou une infrastructure de secours.

---

## 6.7 Retour (Failback)

Retour progressif vers le site principal après restauration.

---

- corruption logicielle.

---

## Sinistres cyber

- ransomware ;

- sabotage.

---

## Sinistres physiques

- incendie ;
- inondation ;
- catastrophe naturelle ;
- coupure électrique prolongée.

---

## Sinistres Cloud

- indisponibilité régionale ;
- perte de services managés ;
- panne d’un fournisseur.

---

## Sinistres humains

- erreur de manipulation ;
- suppression accidentelle ;
- mauvaise configuration.

# 10. Stratégies de reprise

## Sauvegarde + restauration

La plus classique.

---

## Réplication synchrone

Aucune perte de données.

---

## Réplication asynchrone

Faible perte acceptable.

---

## Site chaud (Hot Site)

Production quasiment immédiate.

---

## Site tiède (Warm Site)

Infrastructure partiellement préparée.

---

## Site froid (Cold Site)

Infrastructure disponible mais nécessitant une installation.

---

## Multi-Région Cloud

Plusieurs régions fonctionnent simultanément.

---

## Active-Active

Deux centres fonctionnent en permanence.

---

## Active-Passive

Le second site attend la bascule.

# 22. Cas d’usage EduWeb

## EduWeb Planner

La région Cloud principale devient indisponible.

Le PRA :

- active la région secondaire ;
- restaure les bases ;
- redirige le trafic ;
- valide les emplois du temps.

---

## EduWeb Governance

Corruption de la base documentaire.

Le PRA :

- restaure le snapshot ;
- vérifie les signatures ;
- rejoue les journaux.

---

## EduWeb Booking

Perte complète d'un serveur.

Le système :

- recrée automatiquement les conteneurs ;
- restaure les données ;
- remet le service en ligne.

---

## Ministère

↓

↓

# 27. Conclusion

Le **Plan de Reprise d’Activité (PRA)** constitue le prolongement opérationnel du **Plan de Continuité d’Activité (OPS-009)**. Là où le PCA vise à maintenir les activités essentielles pendant une crise, le PRA fournit les procédures techniques permettant de restaurer les infrastructures, les applications et les données après un sinistre.

En s'appuyant sur des sauvegardes fiables, des mécanismes de réplication, des sites de secours, l'Infrastructure as Code et des orchestrateurs de reprise automatisés, EduWeb peut réduire significativement les temps d'interruption tout en garantissant l'intégrité des informations et la reprise progressive des services. Les exercices réguliers, l'automatisation et l'amélioration continue assurent que le dispositif reste opérationnel face à l'évolution des risques.

Le document suivant (**OPS-011 — Gestion de la Capacité**) traitera de l'anticipation des besoins en ressources, de la planification des capacités et de l'optimisation des infrastructures afin de prévenir les situations de saturation et d'assurer une croissance maîtrisée de l'écosystème EduWeb.
