# OPS-003 — Observabilité (Enterprise Observability Architecture)

> **Objectif :** Définir l'architecture d'observabilité d'EduWeb afin de fournir une compréhension complète, en temps réel et prédictive du comportement des systèmes, des applications, des services, des infrastructures et des processus métier.

# 1. Introduction

La supervision répond principalement à la question :

> **Que se passe-t-il ?**

L'observabilité répond à une question plus ambitieuse :

> **Pourquoi cela se passe-t-il ?**

L'observabilité permet d'expliquer le comportement interne d'un système complexe grâce à l'analyse combinée :

- des métriques ;
- des journaux ;
- des traces distribuées.

Elle constitue une capacité indispensable dans une architecture basée sur les microservices, l'intelligence artificielle et le Cloud.

---

# 2. Vision

EduWeb adopte une architecture d'observabilité globale permettant :

- une visibilité complète du système ;
- une compréhension des causes profondes ;
- une détection prédictive des dégradations ;
- une amélioration continue des performances.

L'observabilité devient un outil permanent d'aide à l'exploitation et à la gouvernance.

---

# 3. Objectifs

L'architecture poursuit plusieurs objectifs :

- comprendre le comportement des systèmes ;
- accélérer le diagnostic des incidents ;
- réduire le temps moyen de résolution (MTTR) ;
- améliorer la résilience ;
- faciliter les analyses post-incidents ;
- alimenter les moteurs AIOps.

---

# 4. Principes directeurs

# 6. Les trois piliers de l'observabilité

## 6.1 Les métriques

Les métriques mesurent quantitativement le fonctionnement du système.

Exemples :

- utilisation CPU ;
- mémoire ;
- temps de réponse ;
- nombre de requêtes ;
- taux d'erreur ;
- disponibilité.

Les métriques permettent de suivre les tendances.

---

## 6.2 Les journaux (Logs)

Les journaux enregistrent les événements produits par les applications.

Exemples :

- authentification ;
- erreurs ;
- avertissements ;
- transactions ;
- traitements métiers.

Les logs permettent de reconstruire les événements.

---

## 6.3 Les traces distribuées

Les traces suivent une requête à travers plusieurs services.

Exemple :

```text
Navigateur

↓

API Gateway

↓

Service Authentification

↓

Service Emploi du Temps

↓

Base de données

↓

Réponse utilisateur
```

Les traces permettent d'identifier précisément où apparaît un ralentissement.

# 9. Analyse intelligente

L'observabilité intègre plusieurs mécanismes avancés.

---

Détecte les écarts par rapport au fonctionnement normal.

---

Utilise l'intelligence artificielle pour identifier :

- comportements inhabituels ;
- dérives progressives ;
- incidents émergents.

## Analyse causale

Recherche les causes profondes.

---

## Analyse prédictive

# 10. Corrélation et diagnostic

L'observabilité fusionne les informations provenant des trois piliers.

### Exemple

```text
Temps de réponse élevé

↓

CPU normal

↓

Mémoire normale

↓

Journal d'erreur SQL

↓

Trace bloquée sur Database Service

↓

Cause identifiée :

Verrouillage de la base de données
```

Le diagnostic est produit automatiquement.

# 11. Gouvernance

Chaque donnée d'observabilité comporte :

- un identifiant ;
- un horodatage ;
- une source ;
- un environnement ;
- un niveau de criticité ;
- une durée de conservation.

Toutes les données sont :

- historisées ;
- sécurisées ;
- auditables ;
- exploitables.

# Exemple 1 — EduWeb Planner

Un calcul d'emploi du temps devient anormalement lent.

Les métriques montrent :

- CPU normal ;
- mémoire normale.

Les traces révèlent une attente excessive sur une API externe.

Le système identifie immédiatement la cause.

---

# Exemple 2 — EduWeb Governance

Les validations administratives ralentissent.

Les logs montrent :

- une erreur de synchronisation.

Les traces permettent d'isoler précisément le microservice responsable.

---

# Exemple 3 — EduWeb Booking

Une réservation échoue.

Les traces montrent :

- API Gateway ;
- Service Booking ;
- Service Paiement.

Le diagnostic révèle un délai d'expiration du fournisseur de paiement.

---

# Exemple 4 — Ministère

Pendant une campagne nationale, plusieurs régions signalent des lenteurs.

L'observabilité démontre que :

- les infrastructures sont saines ;
- le problème provient d'une base de données partagée.

Une action ciblée est engagée.

# Conclusion

L'**Observabilité** constitue une évolution majeure par rapport à la simple supervision. En combinant les métriques, les journaux et les traces distribuées, elle permet de comprendre en profondeur le comportement des systèmes complexes et d'identifier rapidement les causes racines des anomalies. Intégrée aux capacités d'analyse avancée et d'intelligence artificielle d'EduWeb, elle fournit une vision unifiée de l'état de santé des infrastructures, des applications et des processus métier. Cette architecture prépare les fondations des **AIOps** et du **Site Reliability Engineering (SRE)**, en rendant possible une exploitation proactive, prédictive et progressivement autonome de l'ensemble de l'écosystème EduWeb.
