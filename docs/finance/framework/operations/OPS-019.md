# 1. Introduction

Les plateformes numériques d’EduWeb constituent un écosystème composé notamment de :

- services web ;
- applications mobiles ;
- API ;
- microservices ;
- bases de données ;
- infrastructures Cloud ;
- systèmes de notification ;
- services de paiement ;
- plateformes d’apprentissage ;
- outils de gestion administrative ;
- services d’intelligence artificielle ;
- systèmes exploités par des partenaires externes.

La multiplication des composants, des utilisateurs, des établissements et des dépendances crée un environnement opérationnel complexe.

Une gestion fragmentée des opérations peut entraîner :

- une faible visibilité globale ;
- des alertes dispersées ;
- des diagnostics tardifs ;
- des responsabilités imprécises ;
- une mauvaise coordination ;
- des incidents prolongés ;
- une communication incohérente ;
- des violations de SLA ;
- une perte de confiance des utilisateurs.

Le Centre d’Exploitation Intelligent, ou **Intelligent Operations Center**, constitue le point central de supervision, de coordination, de décision et de communication opérationnelle.

Il ne s’agit pas uniquement d’une salle équipée d’écrans.

Il s’agit d’un dispositif intégré combinant :

```text
Personnes

+

Processus

+

Technologies

+

Données

+

Automatisation

+

Intelligence artificielle

=

Centre d’Exploitation Intelligent
```

Le Centre d’Exploitation Intelligent d’EduWeb doit fournir une vision globale et en temps réel de la santé des services tout en coordonnant les actions nécessaires à leur maintien, à leur restauration et à leur amélioration.

# 9. Modèle organisationnel

Le Centre peut être organisé selon plusieurs modèles.

## 9.1 Modèle centralisé

Toutes les fonctions sont regroupées dans une seule équipe.

Avantages :

- coordination simple ;
- visibilité unifiée ;
- standardisation.

Limites :

- risque de surcharge ;
- éloignement des équipes produit ;
- dépendance à une structure unique.

---

## 9.2 Modèle fédéré

Une équipe centrale coordonne plusieurs équipes spécialisées.

```text
Centre central

├── Équipe plateforme
├── Équipe réseau
├── Équipe applications
├── Équipe sécurité
├── Équipe données
└── Équipes produits
```

---

## 9.3 Modèle hybride

Le Centre centralise :

- la supervision ;
- les incidents majeurs ;
- la communication ;
- les outils ;
- les normes.

Les équipes produits conservent :

- l’expertise ;
- les runbooks ;
- les remédiations ;
- l’amélioration.

---

## 9.4 Modèle recommandé pour EduWeb

EduWeb adopte progressivement un modèle hybride.

```text
Centre d’Exploitation Intelligent

+

Équipes produits autonomes

+

Équipes spécialisées

+

Fournisseurs intégrés
```

Prévisions de charge

Capacité réservée

Tableaux dédiés

↓

Surveillance des générations

↓

Astreinte renforcée

Les indicateurs surveillés incluent :

- demandes de génération ;
- longueur de file ;
- temps de calcul ;
- taux de réussite ;
- erreurs ;
- capacité restante.

---

## 52.2 Incident de génération

Le moteur de génération devient lent.

Le Centre observe :

```text
Latence élevée

+

File en croissance

+

Workers saturés

+

Taux d’échec en hausse
```

Actions :

- création d’incident ;
- mobilisation du SRE ;
- autoscaling ;
- activation d’un mode asynchrone ;
- communication aux établissements ;
- suivi du rétablissement.

---

## 52.3 EduWeb Governance

Une base documentaire devient indisponible.

Le Centre :

- identifie les services affectés ;
- bascule vers une réplication ;
- active le mode lecture seule ;
- informe les utilisateurs ;
- suit la restauration.

---

## 52.4 EduWeb Booking

Une hausse de conflits de réservation est détectée.

L’analyse révèle :

- une configuration récente ;
- une transaction trop longue ;
- une forte concurrence.

Le Centre coordonne :

- rollback ;
- correction ;
- surveillance ;
- validation métier.

---

## 52.5 E-School EduWeb

Pendant une évaluation nationale, le Centre surveille :

- connexions simultanées ;
- soumissions ;
- latence ;
- erreurs ;
- capacité ;
- état des fournisseurs.

En cas de dégradation :

- autoscaling ;
- priorisation des soumissions ;
- limitation des fonctions secondaires ;
- communication aux responsables.

---

## 52.6 EduWeb Family

Le fournisseur de paiement devient instable.

Le Centre :

- détecte la hausse des erreurs ;
- ouvre le circuit breaker ;
- met les paiements en attente ;
- escalade le fournisseur ;
- informe les utilisateurs ;
- rejoue les transactions après rétablissement.

---

## 52.7 Incident réseau régional

Plusieurs établissements d’une même zone signalent des difficultés.

Le Centre corrèle :

- géographie ;
- opérateur ;
- latence ;
- pertes réseau ;
- tickets.

Il identifie un incident régional au lieu de traiter chaque établissement séparément.

---

## 52.8 Expiration de certificat

Un certificat expire dans quatorze jours.

Le Centre :

- crée une tâche ;
- déclenche le renouvellement ;
- vérifie le déploiement ;
- escalade en cas d’échec ;
- clôture après validation.

---

## 52.9 Déploiement Canary

Le Centre compare :

- erreurs ;
- latence ;
- résultats métier ;
- consommation ;
- SLO.

La promotion est autorisée uniquement si les indicateurs restent conformes.

- communique avec les autorités ;
- suit la reprise ;

# 58. Conclusion

Le **Centre d’Exploitation Intelligent** constitue le cœur du pilotage opérationnel de l’écosystème EduWeb.

Il rassemble dans une même capacité d’entreprise :

```text
Supervision

+

Observabilité

+

ITSM

+

SRE

+

AIOps

+

DevSecOps

+

Automatisation

+

Coordination humaine
```

Il permet à EduWeb de disposer d’une vision cohérente et en temps réel de la santé de ses plateformes, de détecter rapidement les anomalies, de coordonner les incidents, d’automatiser les remédiations sûres et de communiquer efficacement avec les utilisateurs, les établissements, les partenaires et les autorités.

Le Centre ne doit pas être réduit à une infrastructure technique ou à une salle d’écrans. Sa valeur repose sur la combinaison de processus normalisés, de responsabilités claires, de compétences adaptées, de données fiables et de technologies intégrées.

Son modèle hybride, associant un centre central, des équipes produits, des experts spécialisés, des relais régionaux et des fournisseurs, permet de répondre aux besoins d’une plateforme éducative nationale et multi-services.

À mesure que la maturité augmente, le Centre évolue d’un modèle de supervision réactive vers une exploitation prédictive et automatisée. Cette progression doit cependant rester gouvernée, auditable et fondée sur des mécanismes de contrôle humain pour toute action présentant un risque important.

Le document suivant, **OPS-020 — Architecture Opérationnelle Cible**, consolidera l’ensemble des principes, processus, capacités, rôles, technologies et trajectoires définis dans la collection OPS afin de présenter la vision cible globale des opérations d’EduWeb.
