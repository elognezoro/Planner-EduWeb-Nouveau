# 1. Introduction

Le **Site Reliability Engineering (SRE)** est une discipline d’ingénierie qui applique les principes du développement logiciel à l’exploitation des systèmes d’information.

Son objectif n'est pas simplement de maintenir les services en fonctionnement, mais d'améliorer continuellement leur fiabilité.

Le SRE cherche à répondre à des questions telles que :

- Quelle disponibilité est réellement nécessaire ?
- Quelle quantité de panne est acceptable ?
- Quels investissements apportent le meilleur gain de fiabilité ?
- Quelles tâches doivent être automatisées ?
- Quand faut-il privilégier la stabilité plutôt que les nouvelles fonctionnalités ?

Pour EduWeb, le SRE constitue le lien entre :

- les besoins métier ;
- les équipes de développement ;
- les équipes d'exploitation ;
- la cybersécurité ;
- l'AIOps ;
- le DevSecOps.

EduWeb adopte une approche SRE reposant sur :

- la réduction du travail répétitif ;

# 6. Concepts fondamentaux

## 6.1 SLI

Mesure objective de la qualité d'un service.

Exemples :

- disponibilité ;
- latence ;
- taux d'erreur.

---

## 6.2 SLO

Objectif associé à un SLI.

Exemple :

```text
99,95 % de disponibilité mensuelle
```

---

## 6.3 SLA

Engagement contractuel.

Le SLO est généralement plus exigeant que le SLA.

---

## 6.4 Error Budget

Part d'indisponibilité acceptable.

```text
Error Budget

=

100 %

-

SLO
```

---

## 6.5 Toil

Travail répétitif :

- manuel ;
- sans valeur ajoutée ;
- automatisable.

---

## 6.6 Blameless Postmortem

Analyse d'incident sans recherche de culpabilité.

# 13. Error Budgets

Lorsque le budget est consommé :

- réduction des déploiements ;
- stabilisation ;
- correction des problèmes ;
- revue technique.

L'innovation est temporairement ralentie.

---

# 14. Fiabilité orientée utilisateur

Le SRE mesure :

- ce que voit réellement l'utilisateur ;
- non uniquement l'état des serveurs.

Exemple :

Le serveur est disponible.

Mais :

```text
Impossible de générer un emploi du temps.
```

Le service est considéré comme dégradé.

# 42. Conclusion

Le **Site Reliability Engineering** constitue le socle de la fiabilité opérationnelle d'EduWeb.

Il repose sur une approche scientifique fondée sur :

- les mesures objectives (SLI) ;
- les objectifs de fiabilité (SLO) ;
- les budgets d'erreur ;
- l'automatisation des opérations ;
- la réduction du travail répétitif (*Toil*) ;
- les analyses post-incident sans recherche de culpabilité (*Blameless Postmortems*) ;
- une culture d'amélioration continue.

Le SRE crée un équilibre entre innovation et stabilité. Les budgets d'erreur servent de mécanisme d'arbitrage : lorsqu'ils sont disponibles, les équipes peuvent accélérer les évolutions ; lorsqu'ils sont consommés, la priorité est donnée au renforcement de la fiabilité.

Intégré au DevSecOps, à l'AIOps, à l'observabilité et aux pratiques de gestion des services, le SRE permet à EduWeb d'exploiter des plateformes nationales hautement disponibles, résilientes et évolutives tout en améliorant durablement l'expérience des utilisateurs.

Le document suivant, **OPS-019 — Centre d'Exploitation Intelligent**, décrira l'organisation, les processus, les outils, les tableaux de bord et les mécanismes de coordination permettant de superviser et de piloter en temps réel l'ensemble de l'écosystème opérationnel d'EduWeb.
