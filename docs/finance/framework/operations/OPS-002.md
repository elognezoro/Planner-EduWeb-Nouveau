# OPS-002 — Supervision et Monitoring (Enterprise Monitoring Architecture)

> **Objectif :** Définir l'architecture de supervision et de monitoring d'EduWeb afin d'assurer une surveillance continue, proactive et intelligente de l'ensemble des infrastructures, applications, services, données et processus métier.

# 1. Introduction

La supervision constitue la première ligne de défense d'une plateforme numérique.

Son rôle est de répondre en permanence aux questions suivantes :

- Tous les services fonctionnent-ils normalement ?
- Les performances sont-elles conformes ?
- Une anomalie est-elle en cours ?
- Une dégradation est-elle prévisible ?
- Une intervention est-elle nécessaire ?

Une supervision efficace permet de détecter les problèmes avant qu'ils n'affectent les utilisateurs.

---

# 2. Vision

EduWeb met en œuvre une supervision :

- continue ;
- centralisée ;
- distribuée ;
- temps réel ;
- intelligente ;
- prédictive.

La plateforme doit être capable non seulement de détecter les incidents, mais également d'en anticiper l'apparition grâce aux analyses avancées et à l'intelligence artificielle.

---

# 3. Objectifs

Le système poursuit les objectifs suivants :

- surveiller tous les composants ;
- détecter rapidement les anomalies ;
- réduire le temps moyen de détection (MTTD) ;
- alimenter les processus AIOps ;
- améliorer la disponibilité des services ;
- produire des indicateurs fiables.

---

# 4. Principes directeurs

La supervision repose sur les principes suivants :

- Monitoring by Default
- Real-Time First
- End-to-End Visibility
- Automation First
- Event-Driven Monitoring
- Low False Positives
- Predictive Monitoring
- Continuous Improvement

La supervision doit couvrir l'ensemble de la chaîne de valeur numérique.

## Monitoring Agents

Installés sur les composants à superviser.

Ils remontent :

- métriques ;
- événements ;
- états.

---

## Metrics Collector

Centralise :

- CPU ;
- mémoire ;
- disque ;
- réseau ;
- disponibilité ;
- indicateurs applicatifs.

---

## Monitoring Engine

Analyse les métriques.

Détecte :

- dépassements de seuils ;
- comportements anormaux ;
- dérives.

---

## Event Correlation Engine

Fusionne plusieurs événements liés.

Exemple :

```text
CPU élevé

+

Mémoire saturée

+

Temps de réponse important

↓

Un seul incident
```

---

## Alert Manager

Gère :

- les priorités ;
- les escalades ;
- les notifications ;
- les acquittements.

---

## Dashboard Platform

Fournit une vision :

- temps réel ;
- historique ;
- stratégique.

# 10. Corrélation des événements

La plateforme ne traite pas les événements isolément.

Elle recherche les relations entre eux.

Exemple :

```text
Base de données lente

↓

API ralenties

↓

Temps de réponse élevé

↓

Réclamations utilisateurs

↓

Incident majeur
```

Une seule alerte consolidée est produite.

---

# 11. Gouvernance

Chaque événement possède :

- un identifiant ;
- une source ;
- un horodatage ;
- une gravité ;
- un statut ;
- un responsable.

Tous les événements sont :

- historisés ;
- auditables ;
- exploitables pour les analyses futures.

# Exemple 1 — EduWeb Planner

Le moteur détecte :

- augmentation des temps de calcul des emplois du temps ;
- saturation mémoire.

Une alerte est générée avant que les utilisateurs ne constatent une dégradation.

---

# Exemple 2 — EduWeb Governance

Le monitoring constate :

- ralentissement des validations administratives.

Le système identifie automatiquement le microservice responsable.

---

# Exemple 3 — EduWeb Booking

Le moteur observe une augmentation du nombre d'échecs de réservation.

L'analyse révèle une indisponibilité partielle de la base de données.

Une intervention est déclenchée.

---

# Exemple 4 — Ministère

Pendant les affectations nationales, la charge est multipliée par dix.

Le système :

- surveille les ressources ;
- augmente automatiquement les capacités cloud ;
- maintient les SLA.

# Conclusion

La **Supervision et le Monitoring** constituent le socle de la maîtrise opérationnelle de l'écosystème EduWeb. En assurant une surveillance continue des infrastructures, des applications, des services, des composants d'intelligence artificielle et des processus métier, cette architecture permet de détecter rapidement les anomalies, de corréler les événements et de déclencher des actions adaptées avant que les utilisateurs ne soient impactés. Elle prépare également les fondations de l'**Observabilité** (OPS-003), qui enrichira cette supervision par une compréhension approfondie des comportements internes du système grâce aux métriques, journaux et traces distribuées.
