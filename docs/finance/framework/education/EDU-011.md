# 1. Introduction

La classe virtuelle permet de réunir à distance des apprenants, des enseignants, des formateurs, des tuteurs ou des professionnels dans un environnement numérique synchrone.

Elle ne doit pas être considérée comme une simple visioconférence.

Une classe virtuelle efficace combine :

- présence pédagogique ;
- interaction ;
- ressources ;
- activités ;
- collaboration ;
- évaluation ;
- suivi ;
- accompagnement ;
- traçabilité.

Dans l’écosystème EduWeb, la classe virtuelle constitue un service transversal pouvant soutenir :

- l’enseignement scolaire ;
- la formation universitaire ;
- la formation professionnelle ;
- l’accompagnement à domicile ;
- les réunions pédagogiques ;
- les séminaires ;
- les soutenances ;
- les évaluations orales ;
- la formation continue ;
- la continuité pédagogique en situation de crise.

L’Architecture des Classes Virtuelles définit le cadre permettant d’organiser ces usages de manière cohérente, accessible, sécurisée et pédagogiquement pertinente.

---

# 2. Finalité

Cette architecture vise à :

- assurer la continuité pédagogique ;
- faciliter l’accès à l’enseignement à distance ;
- renforcer les interactions entre enseignants et apprenants ;
- soutenir les parcours hybrides ;
- permettre les activités collaboratives ;
- améliorer l’accompagnement ;
- faciliter l’accès à des experts éloignés ;
- réduire certaines contraintes géographiques ;
- proposer des séances enregistrables et réutilisables ;
- intégrer les données de participation aux Learning Analytics.

---

# 3. Définition

Une **classe virtuelle** est un environnement numérique synchrone permettant à plusieurs participants d’interagir à distance, en temps réel, dans le cadre d’une activité pédagogique organisée.

Elle peut intégrer :

- audio ;
- vidéo ;
- messagerie instantanée ;
- partage d’écran ;
- présentation ;
- tableau blanc ;
- sondage ;
- sous-groupes ;
- partage de fichiers ;
- annotation ;
- enregistrement ;
- contrôle de présence ;
- évaluation rapide.

---

# 4. Vision

EduWeb promeut une classe virtuelle :

- centrée sur l’apprentissage ;
- interactive ;
- accessible ;
- inclusive ;
- mobile ;
- sécurisée ;
- intégrée aux parcours ;
- traçable ;
- compatible avec les environnements à faible connectivité ;
- gouvernée par des règles pédagogiques explicites.

La classe virtuelle doit compléter les autres modalités d’apprentissage et non reproduire à distance une pédagogie exclusivement magistrale.

```text

   ↓

   ↓

   ↓

   ↓
Interaction
   ↓
Activité
   ↓
Mise en commun
   ↓
Évaluation rapide
   ↓
Synthèse
   ↓

```

Exemple de séance de soixante minutes :

| Phase | Durée indicative |
|---|---:|
| Accueil et vérification | 5 min |
| Introduction | 5 min |
| Apport structuré | 15 min |
| Activité interactive | 15 min |
| Travail en groupe | 10 min |
| Mise en commun | 5 min |
| Évaluation et synthèse | 5 min |

La durée des phases doit être adaptée au public et au niveau d’attention.

# 26. Faible connectivité et mode dégradé

L’architecture doit fonctionner dans des contextes de faible débit.

Les mesures comprennent :

- désactivation facultative de la vidéo ;
- qualité vidéo adaptative ;
- mode audio uniquement ;
- support téléchargeable ;
- enregistrement compressé ;
- accès téléphonique lorsque possible ;
- chat textuel ;
- synchronisation différée ;
- diffusion de diapositives légères ;
- rediffusion à basse résolution ;
- reprise après déconnexion ;
- conservation locale temporaire.

```text
Connexion stable
   → Audio + vidéo + interaction complète

Connexion moyenne
   → Audio + présentation

Connexion faible
   → Audio uniquement + chat

Connexion interrompue
   → Ressource hors ligne + reprise différée
```

Une modalité de remplacement doit être prévue pour les participants durablement empêchés.

- suivre les parcours ;
- cibler les remédiations ;
- analyser la qualité technique.

Les indicateurs ne doivent pas être utilisés pour surveiller excessivement les participants.

# 37. Conclusion

L’**Architecture des Classes Virtuelles** permet à EduWeb d’organiser des activités synchrones à distance qui soient réellement pédagogiques, interactives, accessibles et sécurisées.

Elle structure l’ensemble du cycle de vie d’une session, depuis la planification jusqu’à l’analyse des résultats, en intégrant les rôles, les ressources, les interactions, les évaluations, les enregistrements et les données de participation.

Cette architecture doit répondre aux réalités des systèmes éducatifs, notamment la diversité des équipements, la faible connectivité, la protection des mineurs, les besoins d’accompagnement et la nécessité d’une continuité pédagogique.

En intégrant les classes virtuelles aux parcours, aux ressources, aux évaluations, à EduWeb Planner et aux Learning Analytics, EduWeb peut proposer un environnement synchrone cohérent, pilotable et adapté aux différents publics.

Le document suivant, **EDU-012 — Architecture de l’Apprentissage Hybride**, définira les principes, les modèles, les parcours et les mécanismes d’articulation entre enseignement en présentiel, apprentissage à distance, activités synchrones, activités asynchrones et accompagnement pédagogique.
