# 1. Introduction

Les environnements numériques d’apprentissage produisent de nombreuses données relatives aux activités des apprenants, aux ressources consultées, aux évaluations réalisées, aux interactions pédagogiques et aux parcours suivis.

Ces données peuvent aider les établissements et les enseignants à mieux comprendre :

- les progrès des apprenants ;
- les difficultés rencontrées ;
- les comportements d’apprentissage ;
- les risques de décrochage ;
- l’efficacité des ressources ;
- la pertinence des parcours ;
- la qualité des dispositifs de formation.

Toutefois, leur exploitation doit être organisée, proportionnée, transparente et orientée vers l’amélioration des apprentissages.

L’Architecture des Learning Analytics d’EduWeb établit le cadre permettant de transformer les traces numériques en informations utiles à la décision pédagogique, sans réduire l’apprenant à un simple ensemble de données.

---

# 2. Finalité

Cette architecture vise à :

- améliorer le suivi pédagogique ;
- détecter précocement les difficultés ;
- soutenir la personnalisation ;
- orienter les actions de remédiation ;
- améliorer la qualité des parcours ;
- mesurer l’engagement ;
- renforcer la réussite ;
- faciliter le pilotage des établissements ;
- soutenir les décisions institutionnelles ;
- développer une culture éducative fondée sur les données.

---

# 3. Définition

Les **Learning Analytics**, ou analytique de l’apprentissage, désignent la collecte, la mesure, l’analyse et la communication des données relatives aux apprenants et à leurs contextes afin de comprendre et d’optimiser les apprentissages.

Ils portent notamment sur :

- les activités ;
- les interactions ;
- les résultats ;
- les rythmes ;
- les compétences ;
- les parcours ;
- les ressources ;
- les contextes d’apprentissage.

---

# 4. Vision

EduWeb promeut des Learning Analytics :

- centrés sur la réussite de l’apprenant ;
- utiles aux professionnels de l’éducation ;
- compréhensibles ;
- transparents ;
- sécurisés ;
- responsables ;
- inclusifs ;
- explicables ;
- interopérables ;
- orientés vers l’action.

L’objectif n’est pas de surveiller les apprenants, mais de mieux les accompagner.

---

# 5. Objectifs stratégiques

Les objectifs stratégiques sont :

- mettre en place un système unifié de données d’apprentissage ;
- fournir des tableaux de bord adaptés aux rôles ;
- détecter les risques de décrochage ;
- améliorer les interventions pédagogiques ;
- soutenir la personnalisation des parcours ;
- évaluer l’efficacité des ressources ;
- mesurer la progression des compétences ;
- favoriser la prise de décision fondée sur les données ;
- renforcer la qualité des dispositifs ;
- soutenir le pilotage national ou institutionnel.

# 14. Collecte des traces

La collecte peut s’effectuer à partir :

- d’événements de plateforme ;
- de journaux applicatifs ;
- d’API ;
- de standards xAPI ;
- de connecteurs LMS ;
- de formulaires ;
- d’imports institutionnels ;
- d’enregistrements de présence ;
- de saisies pédagogiques ;
- de synchronisations hors ligne.

Exemple de trace :

```text
Acteur : Apprenant 00452
Action : A terminé
Objet : Activité H5P-CHIM-023
Date : 2026-07-27 10:45
Résultat : 16/20
Durée : 18 minutes
Contexte : Module 2
```

Chaque trace doit comporter une finalité, un identifiant, un horodatage et un contexte.

|---|---|

| Remédiation réussie | Difficultés corrigées / remédiations engagées |

Les indicateurs ne doivent pas être interprétés isolément.

# 18. Analyse descriptive

L’analyse descriptive répond à la question :

> Que s’est-il passé ?

Elle peut montrer :

- le nombre d’apprenants actifs ;
- les taux de connexion ;
- les résultats ;
- les activités terminées ;
- les ressources utilisées ;
- les compétences validées ;
- les abandons ;
- les retards ;
- les tendances temporelles.

Exemple :

```text
1 000 inscrits
   ↓
850 actifs
   ↓
720 parcours achevés
   ↓
650 certifiés
```

Cette analyse constitue le premier niveau de compréhension.

---

# 19. Analyse diagnostique

L’analyse diagnostique répond à la question :

> Pourquoi cela s’est-il produit ?

Elle cherche à identifier :

- les ressources peu efficaces ;
- les notions difficiles ;
- les étapes de rupture ;
- les délais excessifs ;
- les groupes en difficulté ;
- les erreurs fréquentes ;
- les problèmes d’accessibilité ;
- les effets du rythme ;
- les écarts entre modalités.

Exemple :

```text
Baisse des résultats
       ↓
Analyse par module
       ↓
Activité problématique identifiée
       ↓
Consigne ambiguë
       ↓
Révision de la ressource
```

---

# 20. Analyse prédictive

L’analyse prédictive estime la probabilité d’un événement futur.

Elle peut contribuer à prévoir :

- le risque de décrochage ;
- le risque d’échec ;
- le besoin de remédiation ;
- le délai d’achèvement ;
- la réussite probable ;
- la surcharge d’un parcours ;
- la demande de ressources ;
- la participation future.

Les modèles prédictifs doivent être :

- validés ;
- régulièrement réévalués ;
- explicables ;
- contrôlés contre les biais ;
- utilisés comme aide et non comme verdict.

Une prédiction n’est jamais une certitude.

---

# 21. Analyse prescriptive

L’analyse prescriptive répond à la question :

> Quelle action pourrait être engagée ?

Elle peut recommander :

- une ressource complémentaire ;
- un tutorat ;
- une activité de remédiation ;
- un ajustement du rythme ;
- un changement de modalité ;
- une intervention de l’enseignant ;
- une révision du parcours ;
- une orientation vers un module préalable.

```text
Signal détecté
      ↓
Analyse du contexte
      ↓
Options d’intervention
      ↓
Choix humain
      ↓
Action pédagogique
      ↓
Mesure du résultat
```

La recommandation doit rester soumise au jugement du professionnel.

---

# 22. Détection du décrochage

Le risque de décrochage peut être associé à plusieurs signaux :

- absence prolongée ;
- baisse brutale des résultats ;
- activités non terminées ;
- faible fréquence de connexion ;
- retards répétés ;
- échecs successifs ;
- absence d’interaction ;
- diminution du temps d’apprentissage ;
- non-réponse aux messages ;
- abandon d’un module.

Un modèle de détection peut combiner ces signaux.

| Niveau de risque | Action recommandée |
|---|---|
| Faible | Suivi normal |
| Modéré | Message de soutien |
| Élevé | Contact du tuteur |
| Critique | Intervention coordonnée |

Une alerte ne doit jamais entraîner automatiquement une sanction ou une exclusion.

# 27. Éthique et transparence

L’utilisation des Learning Analytics doit respecter les principes suivants :

- informer les utilisateurs ;
- expliquer les finalités ;
- limiter la collecte ;
- éviter la surveillance excessive ;
- empêcher la stigmatisation ;
- permettre la contestation ;
- prévenir les biais ;
- protéger l’autonomie ;
- garantir la proportionnalité ;
- éviter les classements injustifiés.

L’apprenant doit pouvoir comprendre :

- quelles données sont utilisées ;
- dans quel but ;
- qui peut les consulter ;
- combien de temps elles sont conservées ;
- quelles décisions elles influencent ;
- comment demander une correction.

- recommandations ;

# 37. Conclusion

L’**Architecture des Learning Analytics** permet à EduWeb de transformer les traces d’apprentissage en informations utiles à l’accompagnement, à la remédiation, à la personnalisation et au pilotage des systèmes éducatifs.

Elle établit une chaîne cohérente reliant les sources de données, la collecte, la qualité, l’intégration, les analyses, les tableaux de bord, les alertes et les interventions pédagogiques.

Cette architecture ne doit toutefois pas conduire à une surveillance excessive ni à des décisions automatisées opaques. Les analyses doivent rester explicables, proportionnées et soumises au jugement des professionnels de l’éducation.

En combinant données fiables, gouvernance, sécurité, intelligence artificielle responsable et expertise pédagogique, EduWeb peut développer un système analytique capable d’améliorer durablement la réussite des apprenants et la qualité des formations.

Le document suivant, **EDU-011 — Architecture des Classes Virtuelles**, définira les principes, les composants, les processus et les règles de gouvernance nécessaires à l’organisation de séances synchrones d’enseignement, de formation, de collaboration et d’accompagnement à distance.
