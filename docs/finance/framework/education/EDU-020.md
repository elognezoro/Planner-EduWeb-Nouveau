# 1. Introduction

La collection **Education Architecture — EDU** définit les principes et les composants nécessaires à la construction d’un écosystème éducatif numérique cohérent.

Les documents EDU-001 à EDU-019 ont successivement décrit :

- la vision éducative ;
- le référentiel pédagogique ;
- les curricula ;
- les compétences ;
- les parcours ;
- les ressources ;
- les évaluations ;
- les certifications ;
- les compétences numériques ;
- les Learning Analytics ;
- les classes virtuelles ;
- l’apprentissage hybride ;
- l’apprentissage adaptatif ;
- l’intelligence artificielle pédagogique ;
- l’inclusion numérique ;
- la qualité pédagogique ;
- les établissements scolaires ;
- les systèmes éducatifs nationaux ;
- la transformation numérique de l’éducation.

Le présent document consolide ces architectures spécialisées en une vision cible commune.

Il établit les relations entre :

- la stratégie éducative ;
- les capacités métier ;
- les processus pédagogiques ;
- les utilisateurs ;
- les plateformes ;
- les données ;
- les technologies ;
- la gouvernance ;
- la sécurité ;
- l’amélioration continue.

L’Architecture Éducative Cible constitue ainsi la référence de conception et d’évolution de l’écosystème EduWeb.

# 2. Finalité

Cette architecture vise à :

- unifier les différentes composantes éducatives ;
- aligner les plateformes EduWeb sur les finalités pédagogiques ;
- harmoniser les référentiels ;
- faciliter l’interopérabilité ;
- soutenir la transformation numérique ;
- renforcer la qualité des apprentissages ;
- garantir l’inclusion ;
- encadrer les données et l’intelligence artificielle ;
- faciliter le déploiement à l’échelle des établissements ;
- permettre le pilotage national ;
- organiser les responsabilités ;
- orienter les investissements ;
- assurer la durabilité de l’écosystème.

# 4. Vision cible

EduWeb vise un environnement éducatif dans lequel chaque apprenant peut :

- accéder à un parcours adapté ;
- comprendre ses objectifs ;
- utiliser des ressources de qualité ;
- participer à des activités variées ;
- recevoir un accompagnement ;
- être évalué équitablement ;
- faire reconnaître ses compétences ;
- suivre sa progression ;
- apprendre en présentiel ou à distance ;
- utiliser le numérique et l’IA de manière responsable.

Chaque enseignant doit pouvoir :

- accéder aux curricula ;
- planifier ses enseignements ;
- produire des ressources ;
- différencier les apprentissages ;
- organiser des évaluations ;
- analyser les résultats ;
- accompagner les apprenants ;
- collaborer avec ses pairs ;
- utiliser l’IA sous contrôle ;
- développer ses compétences professionnelles.

Chaque établissement doit pouvoir :

- gérer ses acteurs ;
- planifier ses activités ;
- suivre les apprentissages ;
- communiquer avec les familles ;
- gérer ses ressources ;
- produire ses indicateurs ;
- garantir la sécurité ;
- assurer la continuité pédagogique ;
- améliorer ses performances.

Chaque autorité éducative doit pouvoir :

- définir les référentiels ;
- consolider les données ;
- analyser les besoins ;
- soutenir les établissements ;
- piloter les politiques ;
- mesurer les résultats ;
- réduire les inégalités ;
- organiser la transformation numérique.

- apprenant ;
- enseignant ;
- tuteur ;
- parent ;
- professionnel.

## Niveau établissement

- direction ;
- conseil pédagogique ;
- vie scolaire ;
- administration ;
- service numérique ;
- comité qualité.

## Niveau territorial

- inspection ;
- direction régionale ;
- collectivité ;
- structure d’appui.

## Niveau national

- ministères ;
- directions centrales ;
- autorités de certification ;
- gouvernance des données ;
- autorités de contrôle.

Matrice simplifiée :

| Activité | Apprenant | Enseignant | Établissement | Autorité |
|---|---:|---:|---:|---:|
| Réaliser une activité | R | A | S | I |
| Valider une ressource | I | R | A | S |
| Publier un résultat | I | R | A | I |
| Délivrer une certification | I | S | R | A |
| Définir un curriculum | I | C | C | A |
| Gouverner les données | I | C | R | A |

Légende :

- **R** : réalise ;
- **A** : approuve ;
- **S** : soutient ;
- **C** : consulté ;
- **I** : informé.

# 37. Conclusion

L’**Architecture Éducative Cible** constitue la synthèse de la collection EDU et la référence structurante de l’écosystème éducatif EduWeb.

Elle relie dans une architecture cohérente :

- la vision éducative ;
- les curricula ;
- les compétences ;
- les parcours ;
- les ressources ;
- les activités ;
- les évaluations ;
- les certifications ;
- les compétences numériques ;
- les classes virtuelles ;
- l’apprentissage hybride ;
- l’apprentissage adaptatif ;
- l’intelligence artificielle ;
- l’inclusion ;
- la qualité ;
- les établissements ;
- les systèmes éducatifs nationaux ;
- la transformation numérique.

Cette architecture cible permet de dépasser une logique de plateformes indépendantes pour construire un écosystème intégré dans lequel les services, les données, les décisions et les acteurs collaborent autour d’une finalité commune : améliorer durablement l’accès, la qualité et l’équité de l’éducation.

Les plateformes EduWeb occupent des fonctions complémentaires :

- **EduWeb Planner** organise le temps, les contraintes et les ressources pédagogiques ;
- **E-School EduWeb** structure l’apprentissage et l’évaluation ;
- **EduWeb Family** soutient l’accompagnement scolaire ;
- **EduWeb Governance** organise les textes, les procédures et les décisions ;
- **EduWeb Booking** optimise l’utilisation des ressources ;
- **CERTEL** développe et certifie les compétences.

La plateforme de données éducatives assure la cohérence informationnelle, tandis que l’intégration, la sécurité, l’assurance qualité, les Learning Analytics et l’intelligence artificielle responsable permettent d’améliorer progressivement les services.

L’Architecture Éducative Cible ne constitue pas un état figé. Elle représente une direction commune, destinée à évoluer selon :

- les besoins des apprenants ;
- les pratiques des enseignants ;
- les politiques publiques ;
- les progrès scientifiques ;
- les innovations technologiques ;
- les résultats des évaluations ;
- les retours des utilisateurs.

Avec EDU-020, la collection **Education Architecture** est désormais consolidée.

Le document suivant, **GOV-001 — Vision de l’Architecture de Gouvernance**, ouvrira la collection Governance Architecture et définira les principes, les instances, les responsabilités, les droits de décision, les mécanismes de contrôle et les processus d’arbitrage nécessaires au pilotage cohérent de l’écosystème EduWeb.
