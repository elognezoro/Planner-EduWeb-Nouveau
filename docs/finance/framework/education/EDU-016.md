# 1. Introduction

La qualité pédagogique détermine la capacité d’un dispositif éducatif à produire des apprentissages pertinents, durables, équitables et transférables.

Elle ne se limite pas à la qualité d’un contenu ou à la satisfaction immédiate des apprenants. Elle concerne l’ensemble du système éducatif :

- besoins de formation ;
- curricula ;
- compétences ;
- objectifs ;
- parcours ;
- ressources ;
- activités ;
- méthodes ;
- évaluations ;
- accompagnement ;
- plateformes ;
- données ;
- certification ;
- résultats ;
- amélioration continue.

Dans un écosystème numérique comme EduWeb, la qualité pédagogique doit également intégrer :

- l’accessibilité ;
- l’interopérabilité ;
- la sécurité ;
- la fiabilité technique ;
- la protection des données ;
- la pertinence des recommandations ;
- la transparence de l’intelligence artificielle ;
- l’efficacité des dispositifs hybrides ;
- l’expérience utilisateur.

L’Architecture de la Qualité Pédagogique établit un cadre commun permettant de définir, mesurer, contrôler et améliorer la qualité des services éducatifs proposés par EduWeb.

Cette architecture vise à :

- garantir la cohérence des dispositifs éducatifs ;

- harmoniser les pratiques pédagogiques ;

- organiser les audits ;

- soutenir les enseignants et les formateurs ;
- assurer la fiabilité des certifications ;
- intégrer l’amélioration continue dans toutes les plateformes EduWeb.

# 3. Définition

La **qualité pédagogique** désigne la capacité d’un dispositif éducatif à répondre de manière cohérente, efficace, inclusive et mesurable aux besoins des apprenants, des institutions et de la société.

Elle repose sur plusieurs éléments :

- pertinence des objectifs ;
- exactitude des contenus ;
- cohérence des activités ;
- qualité de l’accompagnement ;
- validité des évaluations ;
- accessibilité ;
- équité ;
- efficacité ;
- satisfaction ;
- impact ;
- amélioration continue.

L’**assurance qualité pédagogique** désigne l’ensemble des dispositions organisées permettant de donner confiance dans la capacité d’un dispositif à atteindre les exigences définies.

# 12. Référentiel qualité

Le référentiel qualité constitue la base commune des contrôles.

Il peut être structuré autour des domaines suivants :

1. gouvernance ;
2. conception ;
3. contenus ;
4. activités ;
5. ressources ;
6. accompagnement ;
7. évaluation ;
8. accessibilité ;
9. numérique ;
10. données ;
11. certification ;
12. amélioration.

Chaque exigence doit comporter :

- un code ;
- une description ;
- un niveau de priorité ;
- une preuve attendue ;
- une méthode de contrôle ;
- un responsable ;
- une fréquence de vérification ;
- un statut.

Exemple :

| Code | Exigence | Preuve |
|---|---|---|
| QP-CUR-01 | Les objectifs sont alignés aux compétences | Matrice d’alignement |
| QP-RES-03 | Les ressources sont validées | Fiche de validation |
| QP-EVA-04 | Chaque épreuve possède un corrigé | Corrigé et barème |
| QP-ACC-02 | Les vidéos sont sous-titrées | Fichier de sous-titres |
| QP-IA-01 | Tout usage d’IA est déclaré | Journal d’utilisation |

# 13. Qualité des curricula

La qualité d’un curriculum dépend notamment de :

- sa pertinence ;
- sa cohérence ;
- son alignement avec les besoins ;
- la clarté des compétences ;
- la progressivité ;
- la faisabilité ;
- l’équilibre des contenus ;
- l’actualisation ;
- la contextualisation ;
- la compatibilité avec les volumes horaires ;
- la cohérence des évaluations ;
- les possibilités de passerelle.

Les contrôles portent sur :

- la présence des objectifs ;
- la structure des modules ;
- les prérequis ;
- les redondances ;
- les lacunes ;
- la progression ;
- les charges ;
- les référentiels associés ;
- la conformité institutionnelle.

```text
Besoin
  ↓
Compétence
  ↓
Objectif
  ↓
Contenu
  ↓
Activité
  ↓
Évaluation
```

Tout écart dans cette chaîne réduit la qualité curriculaire.

# 14. Qualité des compétences et objectifs

Les compétences doivent être :

- pertinentes ;
- observables ;
- contextualisées ;
- évaluables ;
- transférables ;
- alignées aux besoins ;
- associées à des critères ;
- organisées par niveau.

Les objectifs d’apprentissage doivent être :

- explicites ;
- mesurables ;
- réalistes ;
- compréhensibles ;
- cohérents avec la durée ;
- alignés à la taxonomie utilisée ;
- associés à une preuve attendue.

Exemple :

| Formulation insuffisante | Formulation améliorée |
|---|---|
| Comprendre Excel | Construire un tableau utilisant SOMME, MOYENNE et SI |
| Connaître l’IA | Analyser les possibilités et les limites d’un outil d’IA |
| Maîtriser Planner | Générer un emploi du temps sans conflit critique |

- durée ;
- règles de progression ;
- possibilités de personnalisation ;
- taux d’achèvement ;
- taux d’abandon ;

- satisfaction ;
- impact.

# 28. Gestion des non-conformités

Une non-conformité correspond à un écart par rapport à une exigence définie.

Exemples :

- ressource non validée ;
- épreuve sans barème ;
- contenu obsolète ;
- vidéo non accessible ;
- certificat délivré sans décision ;
- parcours sans objectifs ;
- usage d’IA non déclaré ;
- absence de suivi ;
- donnée incorrecte ;
- évaluation non sécurisée.

Cycle de traitement :

```text
Détection
   ↓
Enregistrement
   ↓
Classification
   ↓
Analyse
   ↓
Correction immédiate
   ↓
Recherche de cause
   ↓
Action corrective
   ↓
Vérification
   ↓
Clôture
```

Chaque non-conformité doit disposer :

- d’un identifiant ;
- d’une date ;
- d’un propriétaire ;
- d’un niveau de gravité ;
- d’une description ;
- d’une preuve ;
- d’un plan d’action ;
- d’une échéance ;
- d’un statut ;
- d’une validation de clôture.

# 29. Actions correctives et préventives

## Action corrective

Elle élimine la cause d’un écart déjà constaté.

Exemples :

- réviser une ressource ;
- corriger un barème ;
- former un enseignant ;
- modifier une règle ;
- remplacer un outil ;
- renforcer une validation ;
- corriger une donnée.

## Action préventive

Elle réduit la probabilité d’un écart futur.

Exemples :

- ajouter une checklist ;
- automatiser un contrôle ;
- renforcer un tutoriel ;
- améliorer un gabarit ;
- revoir un workflow ;
- mettre en place une alerte ;
- organiser une veille.

Méthodes d’analyse possibles :

- cinq pourquoi ;
- diagramme causes-effets ;
- analyse de processus ;
- analyse de risques ;
- revue de données ;
- retour d’expérience.

# 37. Conclusion

L’**Architecture de la Qualité Pédagogique** permet à EduWeb d’intégrer la qualité à toutes les étapes du cycle éducatif, depuis l’analyse des besoins jusqu’à l’évaluation de l’impact.

Elle établit un cadre commun pour garantir :

- la pertinence des curricula ;
- la clarté des compétences ;
- la cohérence des parcours ;
- la fiabilité des ressources ;
- l’efficacité des activités ;
- la validité des évaluations ;
- la qualité de l’accompagnement ;
- l’accessibilité ;
- la sécurité ;
- la crédibilité des certifications.

Cette architecture ne limite pas la qualité à un contrôle final. Elle la transforme en processus continu associant conception, validation, observation, audit, traitement des écarts et amélioration.

Les Learning Analytics, les tableaux de bord et l’intelligence artificielle peuvent renforcer cette démarche, à condition que les indicateurs restent fiables, interprétables et orientés vers des actions pédagogiques concrètes.

En structurant les responsabilités, les référentiels, les preuves, les audits, les non-conformités et les plans d’amélioration, EduWeb peut développer une culture qualité durable, partagée par les enseignants, les établissements, les apprenants et les autorités éducatives.

Le document suivant, **EDU-017 — Architecture des Établissements Scolaires**, définira les capacités, les processus, les acteurs, les structures organisationnelles, les services numériques et les mécanismes de pilotage nécessaires au fonctionnement d’un établissement scolaire moderne intégré à l’écosystème EduWeb.
