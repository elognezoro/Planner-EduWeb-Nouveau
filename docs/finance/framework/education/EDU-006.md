# 1. Introduction

Les ressources pédagogiques constituent les supports concrets à travers lesquels les apprenants accèdent aux connaissances, réalisent des activités, développent des compétences et reçoivent des rétroactions.

Dans un environnement éducatif numérique, ces ressources prennent des formes multiples :

- documents ;
- vidéos ;
- fichiers audio ;
- illustrations ;
- animations ;
- simulations ;
- exercices interactifs ;
- laboratoires virtuels ;
- études de cas ;
- scénarios pédagogiques ;
- jeux éducatifs ;
- productions générées avec l’aide de l’intelligence artificielle.

L’Architecture des Ressources Pédagogiques d’EduWeb vise à garantir que ces contenus soient pertinents, fiables, accessibles, actualisés, réutilisables et alignés sur les curricula, les compétences et les parcours d’apprentissage.

---

# 2. Finalité

Cette architecture poursuit les finalités suivantes :

- garantir la qualité des contenus éducatifs ;
- faciliter leur création et leur diffusion ;
- assurer leur alignement pédagogique ;
- favoriser leur mutualisation ;
- améliorer leur accessibilité ;
- réduire les duplications inutiles ;
- sécuriser les droits d’utilisation ;
- permettre leur évolution continue ;
- soutenir les différents modes d’apprentissage ;
- renforcer l’efficacité pédagogique.

---

# 3. Définition

Une **ressource pédagogique** est tout contenu, support, outil, document, média ou objet numérique utilisé dans une situation d’enseignement, d’apprentissage, d’accompagnement ou d’évaluation.

Une ressource peut être :

- autonome ;
- intégrée à une séquence ;
- destinée à un enseignant ;
- destinée à un apprenant ;
- utilisée en présentiel ;
- diffusée à distance ;
- interactive ;
- imprimable ;
- adaptable ;
- évaluative.

---

# 4. Vision

EduWeb adopte une vision dans laquelle chaque ressource pédagogique est :

- conçue à partir d’un besoin identifié ;
- reliée à une compétence ;
- intégrée dans un parcours ;
- documentée par des métadonnées ;
- disponible dans plusieurs formats lorsque cela est pertinent ;
- accessible sur différents équipements ;
- versionnée ;
- validée ;
- réutilisable ;
- améliorable à partir des retours d’usage.

La ressource n’est donc pas un simple fichier, mais un composant structuré de l’architecture éducative.

---

# 5. Objectifs stratégiques

Les objectifs stratégiques sont :

- constituer un patrimoine pédagogique numérique ;
- industrialiser la production de contenus ;
- harmoniser les standards de qualité ;
- faciliter l’accès aux ressources ;
- accompagner les enseignants dans la création de contenus ;
- soutenir l’apprentissage personnalisé ;
- valoriser les productions internes ;
- développer des ressources adaptées aux contextes africains ;
- encourager les ressources éducatives libres ;
- assurer l’interopérabilité avec les plateformes éducatives.

---

# 6. Principes directeurs

L’architecture repose sur les principes suivants :

- pertinence pédagogique ;
- exactitude scientifique ;
- centration sur l’apprenant ;
- accessibilité par défaut ;
- modularité ;
- réutilisabilité ;
- traçabilité ;
- interopérabilité ;
- sobriété numérique ;
- respect du droit d’auteur ;
- sécurité ;
- amélioration continue ;
- responsabilité humaine dans l’usage de l’IA.

# 10. Granularité des ressources

Une ressource peut être organisée selon plusieurs niveaux de granularité.

```text
Collection
   └── Cours
       └── Module
           └── Séquence
               └── Activité
                   └── Objet pédagogique
```

La granularité doit être suffisamment fine pour permettre :

- la réutilisation ;
- la personnalisation ;
- la combinaison ;
- la mise à jour partielle ;
- l’adaptation à différents publics.

Exemples d’objets pédagogiques élémentaires :

- une définition ;
- une vidéo de trois minutes ;
- un exercice ;
- une image commentée ;
- une question formative ;
- une simulation ;
- une fiche méthode.

---

# 11. Cycle de vie d’une ressource

Le cycle de vie comprend :

1. expression du besoin ;
2. cadrage ;
3. conception ;
4. production ;
5. révision ;
6. validation ;
7. publication ;
8. utilisation ;
9. analyse des retours ;
10. mise à jour ;
11. archivage ;
12. retrait.

```text
Créer
  ↓
Valider
  ↓
Publier
  ↓
Utiliser
  ↓
Mesurer
  ↓
Améliorer
```

Chaque étape doit disposer de critères de passage clairement définis.

---

# 12. Analyse des besoins

Avant toute production, l’équipe identifie :

- le public cible ;
- le niveau d’étude ;
- les compétences visées ;
- les objectifs d’apprentissage ;
- le contexte d’utilisation ;
- les contraintes techniques ;
- la durée d’usage ;
- le type d’équipement disponible ;
- les besoins d’accessibilité ;
- les langues nécessaires ;
- les modalités d’évaluation associées.

Une ressource ne doit pas être produite uniquement parce qu’un format est disponible ou attractif.

---

# 13. Conception pédagogique

La conception précise :

- la fonction pédagogique de la ressource ;
- le moment de son utilisation ;
- les actions attendues de l’apprenant ;
- le rôle de l’enseignant ;
- les connaissances mobilisées ;
- les compétences développées ;
- les interactions prévues ;
- les modalités de rétroaction ;
- les critères de réussite.

Les principales fonctions pédagogiques sont :

- informer ;
- expliquer ;
- illustrer ;
- démontrer ;
- entraîner ;
- faire expérimenter ;
- évaluer ;
- remédier ;
- guider ;
- motiver.

# 14. Production des contenus

La production peut mobiliser :

- experts disciplinaires ;
- enseignants ;
- ingénieurs pédagogiques ;
- graphistes ;
- vidéastes ;
- développeurs ;
- traducteurs ;
- spécialistes de l’accessibilité ;
- réviseurs ;
- assistants IA sous supervision.

Le processus de production peut être organisé ainsi :

```text
Auteur
  ↓
Ingénierie pédagogique
  ↓
Production multimédia
  ↓
Révision scientifique
  ↓
Contrôle qualité
  ↓
Publication
```

Un gabarit standard doit être utilisé pour chaque type de ressource.

# 15. Métadonnées pédagogiques

Chaque ressource doit être accompagnée de métadonnées structurées.

| Métadonnée | Description |
|---|---|
| Identifiant | Code unique |
| Titre | Nom de la ressource |
| Auteur | Créateur ou responsable |
| Discipline | Domaine concerné |
| Niveau | Public scolaire ou académique |
| Compétence | Compétence visée |
| Objectif | Résultat attendu |
| Type | Vidéo, texte, activité, etc. |
| Durée | Temps estimé d’utilisation |
| Langue | Langue principale |
| Format | PDF, MP4, H5P, HTML, etc. |
| Accessibilité | Adaptations disponibles |
| Licence | Conditions d’utilisation |
| Version | Numéro de version |
| Statut | Brouillon, validé, publié, archivé |
| Date de révision | Prochaine révision prévue |

Ces métadonnées permettent la recherche, la recommandation et l’intégration automatique dans les parcours.

- système éducatif ;

- niveau ;

- compétence ;
- type d’activité ;
- modalité pédagogique ;

- format ;
- difficulté ;
- public cible ;

```text
               ├── Animation
```

- MP4 ;
- WebM ;
- SVG ;
- PNG ;
- JPEG ;

- du niveau d’interactivité ;

# 19. Ressources interactives

Les ressources interactives comprennent :

- quiz ;
- glisser-déposer ;
- textes à trous ;
- vidéos enrichies ;
- cartes mémoires ;
- lignes du temps ;
- jeux sérieux ;
- scénarios à embranchements ;
- simulations ;
- exercices autocorrectifs.

Une ressource interactive doit fournir :

- des consignes claires ;
- une rétroaction immédiate ;
- des critères de réussite ;
- une possibilité de recommencer ;
- une traçabilité des résultats lorsque cela est pertinent.

---

# 20. Ressources immersives

Les technologies immersives peuvent inclure :

- réalité virtuelle ;
- réalité augmentée ;
- visites virtuelles ;
- laboratoires simulés ;
- modèles 3D ;
- environnements de mise en situation.

Ces ressources sont particulièrement utiles lorsque :

- l’expérience réelle est dangereuse ;
- le matériel est coûteux ;
- l’accès au terrain est limité ;
- la répétition est nécessaire ;
- la visualisation spatiale facilite la compréhension.

Le recours à l’immersion doit rester justifié pédagogiquement.

# 21. Ressources générées ou assistées par l’IA

L’intelligence artificielle peut assister :

- la rédaction initiale ;
- la simplification ;
- la traduction ;
- la génération d’exercices ;
- la création d’illustrations ;
- la production de questions ;
- l’adaptation au niveau ;
- la synthèse ;
- la création de variantes ;
- l’analyse de la lisibilité.

Toute ressource produite avec l’aide de l’IA doit faire l’objet de :

- vérification scientifique ;
- contrôle pédagogique ;
- validation éditoriale ;
- vérification des biais ;
- contrôle des droits ;
- identification du responsable humain.

```text
Suggestion IA
      ↓
Révision humaine
      ↓
Validation disciplinaire
      ↓
Contrôle qualité
      ↓
```

# 22. Accessibilité et inclusion

Les ressources doivent respecter une conception inclusive.

Les exigences comprennent :

- texte alternatif pour les images ;
- sous-titrage des vidéos ;
- transcription des fichiers audio ;
- contraste suffisant ;
- navigation au clavier ;
- structure de titres cohérente ;
- police lisible ;
- langage compréhensible ;
- compatibilité avec les lecteurs d’écran ;
- possibilité de télécharger les contenus ;
- version légère pour faible connectivité ;
- adaptation des durées.

L’accessibilité doit être prise en compte dès la conception et non ajoutée en fin de production.

---

# 23. Multilinguisme et contextualisation

Les ressources peuvent être :

- traduites ;
- localisées ;
- contextualisées ;
- adaptées culturellement ;
- enrichies d’exemples locaux ;
- proposées dans des langues nationales.

La contextualisation peut porter sur :

- les noms ;
- les situations ;
- les unités ;
- les références culturelles ;
- les illustrations ;
- les environnements scolaires ;
- les réalités économiques et sociales.

Une traduction littérale ne suffit pas toujours à produire une ressource pédagogiquement pertinente.

# 25. Réutilisation et mutualisation

La réutilisation permet :

- de réduire les coûts ;
- d’accélérer la production ;
- d’améliorer la cohérence ;
- de faciliter la mise à jour ;
- de valoriser les productions existantes.

Une ressource peut être :

- utilisée sans modification ;
- adaptée ;
- traduite ;
- intégrée à un autre parcours ;
- combinée avec d’autres ressources ;
- transformée en activité interactive ;
- rééditée pour un autre niveau.

La réutilisation doit respecter la licence et préserver la traçabilité de l’auteur.

# 26. Gestion des droits et licences

Chaque ressource doit préciser son régime d’utilisation.

Les régimes possibles sont :

- droits réservés ;
- licence institutionnelle ;
- licence commerciale ;
- licence Creative Commons ;
- domaine public ;
- usage interne ;
- usage limité à un établissement ;
- usage ouvert avec attribution.

Les responsabilités incluent :

- vérifier les droits sur les textes ;
- vérifier les droits sur les images ;
- vérifier les droits musicaux ;
- identifier les sources ;
- conserver les autorisations ;
- limiter la diffusion si nécessaire ;
- retirer les contenus litigieux.

# 27. Validation scientifique et pédagogique

La validation doit porter sur deux dimensions complémentaires.

## Validation scientifique

Elle vérifie :

- l’exactitude ;
- l’actualité ;
- la cohérence disciplinaire ;
- la qualité des sources ;
- l’absence d’erreurs factuelles.

## Validation pédagogique

Elle vérifie :

- l’adéquation au public ;
- la clarté ;
- l’alignement avec les objectifs ;
- la charge cognitive ;
- la pertinence des activités ;
- la qualité de la rétroaction ;
- l’accessibilité.

Une ressource ne peut être publiée officiellement sans validation appropriée.

---

# 28. Gestion des versions

Chaque modification significative doit produire une nouvelle version.

Exemple :

| Version | Modification |
|---|---|
| 1.0 | Première publication |
| 1.1 | Correction mineure |
| 1.2 | Ajout d’une activité |
| 2.0 | Révision complète |
| 2.1 | Mise à jour réglementaire |

La gestion des versions doit permettre :

- de connaître l’auteur de la modification ;
- de comparer les versions ;
- de restaurer une ancienne version ;
- d’identifier les parcours impactés ;
- de notifier les utilisateurs concernés.

# 37. Conclusion

L’**Architecture des Ressources Pédagogiques** organise l’ensemble du patrimoine éducatif numérique d’EduWeb, depuis l’expression du besoin jusqu’à la diffusion, à l’évaluation et à l’archivage des contenus.

Elle garantit que chaque ressource est reliée à un objectif, à une compétence, à un public et à un contexte d’utilisation. Elle facilite également la mutualisation, la réutilisation, l’accessibilité et l’amélioration continue des contenus.

En structurant les métadonnées, les workflows de validation, les règles de versionnage, les droits d’utilisation et les mécanismes de diffusion, EduWeb peut constituer un référentiel pédagogique fiable, évolutif et interopérable.

Le document suivant, **EDU-007 — Architecture des Évaluations**, définira les principes, les processus, les instruments, les niveaux de sécurité et les mécanismes de gouvernance permettant de concevoir, administrer, corriger, analyser et améliorer les évaluations éducatives.
