# 1. Introduction

La certification constitue l’aboutissement formel d’un processus d’apprentissage, d’évaluation et de validation des compétences.

Elle représente une preuve reconnue qu’un apprenant, un professionnel ou une institution a satisfait à des exigences définies dans un référentiel.

Dans un environnement numérique, la certification doit répondre à plusieurs défis :

- authenticité ;
- traçabilité ;
- sécurité ;
- interopérabilité ;
- reconnaissance ;
- pérennité ;
- vérifiabilité ;
- protection des données ;
- lutte contre la fraude ;
- adaptation aux parcours modulaires.

L’Architecture des Certifications d’EduWeb définit le cadre permettant de produire des preuves numériques fiables, vérifiables et utilisables dans les systèmes éducatifs, professionnels et administratifs.

---

# 2. Finalité

Cette architecture vise à :

- reconnaître officiellement les acquis ;
- valoriser les compétences développées ;
- sécuriser les certificats délivrés ;
- faciliter leur vérification ;
- éviter les falsifications ;
- permettre la capitalisation des acquis ;
- soutenir la mobilité académique et professionnelle ;
- favoriser la reconnaissance entre institutions ;
- automatiser les processus de délivrance ;
- garantir la traçabilité des décisions.

---

# 3. Définition

Une **certification** est une reconnaissance formelle, délivrée par une autorité habilitée, attestant qu’une personne a satisfait à des critères définis dans un référentiel.

Une certification comprend généralement :

- une autorité émettrice ;
- un bénéficiaire identifié ;
- un référentiel ;
- des compétences validées ;
- des critères de réussite ;
- une date de délivrance ;
- un niveau ;
- une durée de validité éventuelle ;
- une preuve vérifiable ;
- un identifiant unique.

---

# 4. Vision

EduWeb promeut une certification :

- fiable ;
- transparente ;
- sécurisée ;
- portable ;
- vérifiable ;
- interopérable ;
- accessible ;
- fondée sur des preuves ;
- reconnue par les institutions ;
- adaptable à l’apprentissage tout au long de la vie.

La certification numérique ne doit pas être une simple reproduction d’un document papier. Elle doit constituer une preuve structurée, consultable et vérifiable.

---

# 5. Objectifs stratégiques

Les objectifs stratégiques sont :

- constituer un registre fiable des certifications ;
- standardiser les processus de délivrance ;
- soutenir les certifications EduWeb ;
- permettre la vérification par code QR ;
- développer les microcertifications ;
- favoriser les badges numériques ;
- assurer la reconnaissance interinstitutionnelle ;
- faciliter les parcours capitalisables ;
- réduire les délais de délivrance ;
- améliorer la confiance des bénéficiaires et employeurs.

L’architecture repose sur les principes suivants :

- légitimité de l’émetteur ;
- validité des évaluations ;
- unicité du certificat ;
- traçabilité complète ;
- vérification ouverte et contrôlée ;
- protection des données ;
- séparation des rôles ;
- réversibilité ;

# 9. Typologie des certifications

| Type | Finalité |
|---|---|
| Attestation de participation | Confirmer la participation |
| Attestation d’achèvement | Confirmer la fin d’un parcours |
| Certificat de réussite | Confirmer l’atteinte d’un seuil |
| Certificat de compétences | Valider des compétences identifiées |
| Badge numérique | Reconnaître un acquis précis |
| Microcertification | Valider un bloc limité et capitalisable |
| Certification professionnelle | Reconnaître une aptitude métier |
| Certification institutionnelle | Valider une formation interne |
| Diplôme numérique | Reconnaître un parcours académique |
| Accréditation | Reconnaître une organisation ou un programme |
| Habilitation | Autoriser l’exercice d’une fonction déterminée |

---

# 10. Référentiel de certification

Chaque certification doit disposer d’un référentiel décrivant :

- son intitulé ;
- sa finalité ;
- son public cible ;
- les compétences visées ;
- les prérequis ;
- les évaluations requises ;
- les seuils de réussite ;
- les règles de compensation ;
- les preuves attendues ;
- les conditions de délivrance ;
- la durée de validité ;
- les modalités de renouvellement ;
- les règles de recours ;
- les conditions de révocation.

Exemple :

| Élément | Contenu |
|---|---|
| Certification | CERTEL Niveau 1 |
| Compétences | Bureautique, numérique, communication |
| Durée | Trois mois |
| Évaluation | Contrôle continu, projet, examen |
| Seuil | Moyenne générale ≥ 10/20 |
| Validité | Permanente ou selon décision |
| Émetteur | EdTech EduWeb |

---

# 11. Conditions d’éligibilité

Les conditions d’éligibilité peuvent inclure :

- inscription régulière ;
- identité vérifiée ;
- paiement validé le cas échéant ;
- prérequis académiques ;
- expérience professionnelle ;
- validation d’un niveau inférieur ;
- participation minimale ;
- complétude du dossier ;
- respect du règlement ;
- absence de fraude établie.

La plateforme doit pouvoir gérer les règles d’éligibilité selon chaque certification.

---

# 12. Conditions de validation

La validation peut dépendre :

- d’un score minimal ;
- de la réussite à chaque module ;
- d’une moyenne globale ;
- de la validation d’un projet ;
- d’une soutenance ;
- d’un stage ;
- d’un portfolio ;
- d’une présence minimale ;
- de la validation par un jury ;
- de l’absence d’anomalie majeure.

Exemple :

```text
Modules validés
      +
Projet validé
      +
Examen final réussi
      +
Dossier conforme
      =
Certification délivrée
```

---

# 13. Niveaux de certification

Une architecture à plusieurs niveaux peut être utilisée.

| Niveau | Description |
|---|---|
| Niveau 1 | Fondamentaux |
| Niveau 2 | Maîtrise intermédiaire |
| Niveau 3 | Maîtrise avancée |
| Niveau 4 | Expertise |
| Niveau 5 | Expertise stratégique ou formateur |

Chaque niveau doit préciser :

- les compétences attendues ;
- les prérequis ;
- les modalités d’évaluation ;
- les preuves à fournir ;
- les passerelles possibles.

---

# 14. Unités capitalisables

Les unités capitalisables permettent à l’apprenant de valider progressivement une certification.

Exemple :

```text
Certification complète
   ├── Unité 1 : Fondamentaux
   ├── Unité 2 : Pratique
   ├── Unité 3 : Projet
   └── Unité 4 : Évaluation finale
```

Les avantages sont :

- flexibilité ;
- reprise de parcours ;
- reconnaissance partielle ;
- mobilité ;
- progression graduelle ;
- réduction des redondances.

Chaque unité doit disposer d’un identifiant, d’un niveau et d’une durée de validité éventuelle.

---

# 15. Microcertifications

Une microcertification reconnaît une compétence ou un bloc de compétences limité.

Elle doit préciser :

- la compétence visée ;
- le volume d’apprentissage ;
- les critères ;
- les preuves ;
- le niveau ;
- l’émetteur ;
- la date ;
- les possibilités de capitalisation ;
- la relation avec une certification plus large.

Exemples :

- concevoir un tableau Excel ;
- créer une activité H5P ;
- élaborer un emploi du temps ;
- exploiter un outil d’IA de manière responsable ;
- produire un rapport administratif numérique.

---

# 16. Badges numériques

Un badge numérique est une preuve visuelle et structurée d’un acquis.

Il contient généralement :

- le nom du badge ;
- l’identité de l’émetteur ;
- l’identité du bénéficiaire ;
- les critères ;
- la date ;
- la preuve ;
- le référentiel ;
- l’identifiant ;
- l’URL de vérification ;
- la durée de validité éventuelle.

```text
Badge
   ├── Identité
   ├── Compétence
   ├── Critères
   ├── Preuve
   ├── Émetteur
   └── Vérification
```

Les badges peuvent être affichés dans un portfolio ou un passeport de compétences.

---

# 17. Attestations

Les attestations peuvent confirmer :

- une participation ;
- une présence ;
- un achèvement ;
- une contribution ;
- une animation ;
- une formation suivie ;
- une activité institutionnelle.

Elles ne doivent pas être confondues avec une certification de compétence.

Une attestation de participation ne signifie pas nécessairement que les compétences ont été évaluées.

---

# 18. Certificats professionnels

Les certificats professionnels reconnaissent la capacité à exercer une activité ou à mobiliser des compétences métier.

Ils peuvent comporter :

- une épreuve pratique ;
- une mise en situation ;
- une étude de cas ;
- un portfolio ;
- une soutenance ;
- une expérience professionnelle ;
- une validation par jury.

La certification doit être reliée à un référentiel métier clairement identifié.

---

# 19. Diplômes numériques

Un diplôme numérique doit comporter :

- l’identité complète du diplômé ;
- l’intitulé du diplôme ;
- le niveau ;
- la spécialité ;
- l’établissement émetteur ;
- la date de délibération ;
- la date de délivrance ;
- les signatures habilitées ;
- le numéro unique ;
- un mécanisme de vérification ;
- les mentions éventuelles ;
- les références réglementaires.

Le diplôme numérique peut être accompagné d’une version imprimable, sans que cette dernière constitue l’unique preuve.

---

# 20. Jury de certification

Le jury est responsable de la décision finale.

Il peut comprendre :

- un président ;
- des experts disciplinaires ;
- des professionnels ;
- des représentants institutionnels ;
- des enseignants ;
- un secrétaire de séance ;
- un responsable qualité.

Le jury doit disposer :

- des résultats ;
- des preuves ;
- des rapports d’incident ;
- des propositions de validation ;
- des règles de décision ;
- des informations sur les recours.

Les délibérations doivent être tracées dans un procès-verbal sécurisé.

---

# 21. Processus de délivrance

Le processus de délivrance comprend :

1. clôture des évaluations ;
2. consolidation des résultats ;
3. contrôle des dossiers ;
4. validation par le jury ;
5. génération du certificat ;
6. signature ;
7. enregistrement ;
8. notification ;
9. mise à disposition ;
10. archivage.

```text
Résultats consolidés
        ↓
Contrôle
        ↓
Jury
        ↓
Décision
        ↓
Génération
        ↓
Signature
        ↓
Registre
        ↓
Délivrance
```

Aucun certificat officiel ne doit être généré avant la validation formelle.

---

# 22. Identité du bénéficiaire

L’identité doit être fiable et suffisamment vérifiée.

Les données peuvent comprendre :

- nom ;
- prénoms ;
- date de naissance ;
- identifiant apprenant ;
- numéro d’inscription ;
- photographie si nécessaire ;
- pièce justificative ;
- adresse électronique ;
- établissement ;
- pays.

Les procédures doivent prévenir :

- les doublons ;
- les homonymies ;
- les erreurs de saisie ;
- l’usurpation d’identité ;
- les modifications non autorisées.

Toute correction d’identité après délivrance doit être tracée.

---

# 23. Authenticité et vérification

Chaque certification doit être vérifiable.

Les mécanismes peuvent inclure :

- code QR ;
- URL sécurisée ;
- identifiant unique ;
- signature électronique ;
- cachet numérique ;
- empreinte cryptographique ;
- registre de vérification ;
- API de contrôle.

Exemple de vérification :

```text
Utilisateur scanne le QR
        ↓
Portail EduWeb
        ↓
Recherche de l’identifiant
        ↓
Contrôle du statut
        ↓
Affichage des informations autorisées
```

Le portail doit afficher :

- authenticité ;
- statut ;
- émetteur ;
- bénéficiaire ;
- certification ;
- date ;
- validité ;
- révocation éventuelle.

---

# 24. Registre des certifications

Le registre constitue la source officielle.

Il contient :

- numéro unique ;
- bénéficiaire ;
- type de certification ;
- date de délivrance ;
- émetteur ;
- statut ;
- version ;
- compétences validées ;
- référence du jury ;
- date d’expiration ;
- historique des modifications ;
- motif de révocation éventuelle.

Les statuts possibles sont :

- en préparation ;
- délivrée ;
- suspendue ;
- expirée ;
- révoquée ;
- remplacée ;
- archivée.

---

# 25. Révocation, suspension et expiration

Une certification peut être révoquée en cas de :

- fraude ;
- falsification ;
- erreur substantielle ;
- identité erronée ;
- décision judiciaire ;
- non-respect des règles de maintien ;
- délivrance irrégulière.

Une certification peut être suspendue dans l’attente d’une enquête.

Une certification peut expirer lorsque les compétences nécessitent une actualisation régulière.

Le registre doit conserver l’historique complet sans supprimer la trace initiale.

---

# 26. Reconnaissance des acquis

La reconnaissance peut concerner :

- les acquis scolaires ;
- les acquis universitaires ;
- les acquis professionnels ;
- les acquis de l’expérience ;
- les acquis informels ;
- les certifications antérieures ;
- les badges reconnus ;
- les formations réalisées dans une autre institution.

Le processus peut comprendre :

1. dépôt du dossier ;
2. vérification des preuves ;
3. analyse d’équivalence ;
4. entretien ;
5. mise en situation ;
6. décision ;
7. validation partielle ou totale.

---

# 27. Interopérabilité

Les certifications doivent pouvoir être échangées avec :

- plateformes LMS ;
- portfolios numériques ;
- systèmes universitaires ;
- systèmes RH ;
- portails administratifs ;
- services publics ;
- plateformes d’emploi ;
- registres internationaux.

Les standards possibles incluent :

- Open Badges ;
- Verifiable Credentials ;
- Europass ;
- xAPI ;
- LTI ;
- standards d’identité numérique ;
- API REST sécurisées.

L’interopérabilité ne doit pas compromettre la protection des données.

---

# 28. Intelligence artificielle

L’IA peut assister :

- le contrôle de complétude ;
- la détection d’anomalies ;
- la vérification de cohérence ;
- la détection de doublons ;
- l’analyse des preuves ;
- le classement des dossiers ;
- la génération de brouillons de documents ;
- la recommandation de microcertifications ;
- la détection des certifications arrivant à expiration.

L’IA ne doit pas :

- délivrer seule une certification ;
- remplacer le jury ;
- modifier une décision validée ;
- révoquer automatiquement un certificat ;
- prendre une décision opaque ;
- exploiter des données non nécessaires.

La responsabilité finale reste humaine et institutionnelle.

---

# 29. Sécurité et protection des données

Les mesures de sécurité comprennent :

- authentification forte ;
- contrôle des rôles ;
- chiffrement ;
- signature électronique ;
- journalisation ;
- sauvegardes ;
- séparation des environnements ;
- protection des clés de signature ;
- détection des accès suspects ;
- audit périodique ;
- plan de reprise ;
- limitation des données publiques ;
- conservation réglementée.

Les risques principaux sont :

- falsification ;
- vol d’identité ;
- modification de résultats ;
- génération non autorisée ;
- fuite de données ;
- compromission des signatures ;
- duplication frauduleuse ;
- suppression de preuves ;
- indisponibilité du registre.

# 30. Gouvernance

La gouvernance repose sur plusieurs responsabilités.

| Rôle | Responsabilité |
|---|---|
| Autorité certificatrice | Porte la responsabilité juridique |
| Comité de certification | Définit les règles |
| Jury | Décide de la validation |
| Responsable pédagogique | Garantit les compétences |
| Responsable qualité | Contrôle les processus |
| Administrateur du registre | Gère les enregistrements |
| Responsable sécurité | Protège le système |
| Responsable juridique | Vérifie la conformité |
| Responsable des données | Supervise les informations |
| Auditeur | Contrôle la traçabilité |

Les fonctions d’évaluation, de décision, de génération et de publication doivent être séparées autant que possible.

```text
Définir
   ↓
Évaluer
   ↓
Décider
   ↓
Délivrer
   ↓
Vérifier
   ↓
Auditer
   ↓

```

Des audits périodiques doivent vérifier :

- les décisions ;
- les dossiers ;
- les signatures ;
- les identifiants ;
- les révocations ;
- les anomalies ;
- les accès ;
- les sauvegardes.

- identifiant unique ;

- attestations d’achèvement ;

- badges réglementaires ;

- présence ;

# 37. Conclusion

L’**Architecture des Certifications** permet à EduWeb de transformer les résultats d’apprentissage et les compétences validées en preuves officielles, sécurisées et vérifiables.

Elle organise l’ensemble du processus, depuis l’éligibilité du candidat jusqu’à la décision du jury, à la génération du certificat, à son enregistrement et à sa vérification publique.

Cette architecture favorise la confiance des apprenants, des établissements, des employeurs et des autorités éducatives. Elle facilite également la capitalisation des acquis, la mobilité, la reconnaissance des compétences et le développement de certifications numériques adaptées à l’apprentissage tout au long de la vie.

Le document suivant, **EDU-009 — Architecture des Compétences Numériques**, définira les domaines, niveaux, référentiels, parcours et mécanismes d’évaluation permettant de développer et de certifier les compétences numériques des apprenants, des enseignants et des professionnels au sein de l’écosystème EduWeb.
