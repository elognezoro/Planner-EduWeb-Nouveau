# EDU-015 — Architecture de l’Inclusion Numérique

> **Objectif :** Définir l’architecture pédagogique, sociale, fonctionnelle, technologique et organisationnelle permettant de garantir un accès équitable aux plateformes, aux ressources, aux parcours et aux services éducatifs numériques de l’écosystème EduWeb, indépendamment du handicap, du lieu de résidence, de la connectivité, de la langue, de l’équipement, du genre, de l’âge ou de la situation socio-économique.

# 1. Introduction

La transformation numérique de l’éducation peut élargir l’accès aux savoirs, améliorer l’accompagnement et faciliter la continuité pédagogique.

Elle peut toutefois renforcer les inégalités lorsque certains apprenants ne disposent pas :

- d’un équipement adapté ;
- d’une connexion suffisante ;
- de compétences numériques ;
- de ressources accessibles ;
- d’un environnement favorable ;
- d’un accompagnement humain ;
- de contenus dans une langue comprise ;
- de dispositifs adaptés à leur situation.

L’inclusion numérique ne consiste donc pas uniquement à fournir un accès technique à une plateforme. Elle suppose de garantir que chaque utilisateur puisse effectivement :

- accéder au service ;
- comprendre son fonctionnement ;
- utiliser les ressources ;
- participer aux activités ;
- réaliser les évaluations ;
- recevoir un accompagnement ;
- progresser ;
- faire reconnaître ses acquis.

L’Architecture de l’Inclusion Numérique d’EduWeb établit le cadre permettant de concevoir des services éducatifs utilisables par le plus grand nombre.

---

# 2. Finalité

Cette architecture vise à :

- réduire les inégalités d’accès au numérique éducatif ;
- garantir l’accessibilité des plateformes ;
- prendre en compte les situations de handicap ;
- proposer des solutions adaptées à la faible connectivité ;
- développer les compétences numériques de base ;
- favoriser le multilinguisme ;
- assurer la continuité pédagogique dans les zones éloignées ;
- proposer des alternatives hors ligne ;
- faciliter l’accompagnement des publics vulnérables ;
- éviter que la transformation numérique n’exclue certains apprenants ;
- garantir l’équité dans les parcours et les évaluations ;
- mesurer les écarts d’accès et d’usage.

---

# 3. Définition

L’**inclusion numérique éducative** désigne l’ensemble des politiques, pratiques, services, équipements, contenus et mécanismes d’accompagnement permettant à toute personne de bénéficier effectivement des possibilités offertes par le numérique pour apprendre, enseigner, se former, être évaluée et participer à la vie éducative.

Elle couvre notamment :

- l’accès ;
- l’accessibilité ;
- la connectivité ;
- les équipements ;
- les compétences numériques ;
- les langues ;
- l’accompagnement ;
- l’adaptation pédagogique ;
- l’équité ;
- la participation ;
- la protection.

---

# 4. Vision

EduWeb promeut un environnement éducatif dans lequel :

- aucun apprenant n’est exclu pour une raison technique ;
- les services sont accessibles dès leur conception ;
- les contenus sont proposés dans des formats adaptés ;
- les plateformes fonctionnent sur des équipements modestes ;
- des alternatives hors ligne existent ;
- les utilisateurs sont accompagnés ;
- les différences linguistiques sont prises en compte ;
- les besoins particuliers sont reconnus ;
- les décisions automatisées sont contrôlées ;
- les écarts d’usage sont mesurés et corrigés.

La vision peut être résumée ainsi :

> Le numérique éducatif doit élargir les possibilités d’apprentissage et non créer une nouvelle forme d’exclusion.

Les objectifs stratégiques sont :

- développer une approche mobile-first ;

- développer des indicateurs d’équité ;

- garantir des évaluations accessibles et équitables.

Les publics pouvant rencontrer des obstacles comprennent :

- personnes en situation de handicap ;
- apprenants vivant en zone rurale ;
- utilisateurs disposant d’une faible connectivité ;
- familles sans équipement personnel ;
- adultes peu familiarisés avec le numérique ;
- apprenants en reprise d’études ;
- personnes à faible niveau de lecture ;
- utilisateurs de langues minoritaires ;
- apprenants déplacés ;
- personnes temporairement empêchées ;
- utilisateurs de terminaux anciens ;
- familles à faibles revenus ;
- apprenants ayant des besoins éducatifs particuliers ;
- enseignants insuffisamment formés au numérique.

L’identification doit éviter toute stigmatisation et respecter la confidentialité.

La fracture d’accès concerne l’absence ou l’insuffisance de :

- connexion ;
- équipement ;
- énergie ;
- réseau mobile ;
- infrastructure scolaire ;
- point d’accès ;
- solution de recharge ;
- espace de travail ;
- service technique.

Les mesures peuvent inclure :

- équipements mutualisés ;
- salles numériques ;
- centres communautaires ;
- accès Wi-Fi institutionnel ;
- prêts de terminaux ;
- points de téléchargement ;
- ressources sur support physique ;
- solutions solaires ;
- synchronisation locale ;
- partenariats avec les opérateurs.

---

# 13. Fracture d’usage

Disposer d’un équipement ne garantit pas une utilisation effective.

Les obstacles d’usage comprennent :

- interface complexe ;
- manque de confiance ;
- absence d’accompagnement ;
- difficultés de navigation ;
- consignes peu claires ;
- peur de l’erreur ;
- surcharge d’informations ;
- terminologie technique ;
- absence de support ;
- manque de pertinence des services.

Les réponses comprennent :

- parcours d’initiation ;
- tutoriels simples ;
- interfaces guidées ;
- démonstrations ;
- support de proximité ;
- assistance téléphonique ;
- FAQ ;
- accompagnement par les pairs ;
- messages en langage clair ;
- amélioration de l’expérience utilisateur.

---

# 14. Fracture de compétences

La fracture de compétences concerne les écarts dans la capacité à :

- utiliser un appareil ;
- se connecter ;
- gérer un compte ;
- retrouver une ressource ;
- envoyer un devoir ;
- participer à une classe virtuelle ;
- protéger ses données ;
- interpréter une interface ;
- résoudre un incident simple ;
- utiliser l’IA de manière critique.

Les compétences minimales doivent être évaluées par un diagnostic.

```text
Diagnostic
   ↓
Compétences maîtrisées
   ↓
Compétences à renforcer
   ↓
Parcours d’initiation
   ↓
Accompagnement
   ↓
Autonomie progressive
```

# 15. Accessibilité numérique

L’accessibilité numérique garantit que les interfaces et contenus peuvent être utilisés par des personnes ayant différentes capacités.

Les exigences comprennent :

- navigation au clavier ;
- compatibilité avec les lecteurs d’écran ;
- textes alternatifs ;
- contraste suffisant ;
- titres structurés ;
- formulaires correctement étiquetés ;
- sous-titres ;
- transcription ;
- commandes accessibles ;
- temps adaptable ;
- absence de contenu clignotant dangereux ;
- messages d’erreur compréhensibles ;
- zoom sans perte d’information ;
- design responsive.

L’accessibilité doit être testée :

- automatiquement ;
- manuellement ;
- avec des technologies d’assistance ;
- avec des utilisateurs concernés.

# 16. Inclusion des personnes en situation de handicap

## Handicap visuel

Les adaptations comprennent :

- lecteur d’écran ;
- texte alternatif ;
- audio ;
- contraste élevé ;
- grossissement ;
- navigation structurée ;
- commandes vocales.

## Handicap auditif

Les adaptations comprennent :

- sous-titrage ;
- transcription ;
- interprétation en langue des signes lorsque disponible ;
- alertes visuelles ;
- supports écrits ;
- messagerie textuelle.

## Handicap moteur

Les adaptations comprennent :

- navigation au clavier ;
- commandes simplifiées ;
- compatibilité avec les dispositifs adaptés ;
- délais ajustables ;
- zones cliquables suffisamment grandes ;
- limitation des gestes complexes.

## Handicap cognitif

Les adaptations comprennent :

- langage clair ;
- consignes courtes ;
- progression guidée ;
- réduction de la surcharge ;
- repères visuels ;
- répétition ;
- exemples ;
- temps supplémentaire ;
- interface stable.

# 17. Faible connectivité

L’architecture doit être optimisée pour :

- les réseaux instables ;
- les faibles débits ;
- les forfaits limités ;
- les connexions mobiles ;
- les interruptions fréquentes ;
- les latences élevées.

Les mécanismes comprennent :

- compression ;
- chargement progressif ;
- désactivation des vidéos ;
- qualité adaptative ;
- cache local ;
- synchronisation différée ;
- téléchargement préalable ;
- reprise après interruption ;
- limitation des appels réseau ;
- interfaces légères ;
- contenus textuels alternatifs ;
- mode économie de données.

```text
Connexion élevée
   → Expérience complète

Connexion moyenne
   → Ressources optimisées

Connexion faible
   → Audio, texte, images légères

Absence de connexion
   → Mode hors ligne
```

# 18. Accès hors ligne

Le mode hors ligne doit permettre :

- le téléchargement de cours ;
- la consultation de ressources ;
- la réalisation d’exercices ;
- la saisie de réponses ;
- l’enregistrement de progression ;
- la consultation d’un calendrier ;
- la préparation de devoirs ;
- la synchronisation ultérieure ;
- la reprise après interruption.

Cycle :

```text
Connexion disponible
        ↓
Téléchargement
        ↓
Travail hors ligne
        ↓
Enregistrement local
        ↓
Retour de connexion
        ↓
Synchronisation
        ↓
Contrôle des conflits
```

Les conflits de synchronisation doivent être détectés et résolus sans perte de données.

- interface multilingue ;
- contenus traduits ;
- glossaires ;
- langage clair ;
- audio ;
- sous-titrage ;
- adaptation culturelle ;

# 31. Données, éthique et protection

Les données d’inclusion peuvent être sensibles.

Elles peuvent concerner :

- besoins d’accessibilité ;
- type d’équipement ;
- qualité de connexion ;
- langue ;
- assistance nécessaire ;
- difficultés d’usage ;
- adaptations accordées ;
- historique de support.

Les règles comprennent :

- collecte minimale ;
- finalité explicite ;
- accès restreint ;
- confidentialité ;
- absence de stigmatisation ;
- correction possible ;
- durée de conservation limitée ;
- consentement lorsque nécessaire ;
- protection renforcée des mineurs ;
- interdiction d’usage discriminatoire.

Une donnée d’accessibilité ne doit jamais être utilisée pour réduire les possibilités offertes à un apprenant.

# 37. Conclusion

L’**Architecture de l’Inclusion Numérique** permet à EduWeb de faire de l’accessibilité, de l’équité et de la participation effective des exigences fondamentales de la transformation éducative.

Elle traite les différentes formes de fracture numérique liées à l’équipement, à la connectivité, aux compétences, à la langue, au handicap, au territoire et à la situation socio-économique.

Cette architecture impose que les services soient conçus pour fonctionner sur des appareils modestes, dans des environnements à faible débit et avec des modalités hors ligne. Elle prévoit également des ressources accessibles, des évaluations adaptées, un accompagnement humain et des mécanismes de suivi des écarts.

L’intelligence artificielle peut renforcer l’accessibilité par la transcription, la traduction, la synthèse vocale ou l’adaptation des contenus, mais son utilisation doit rester sécurisée, contrôlée et équitable.

En intégrant l’inclusion dès la conception des plateformes, des parcours, des ressources et des évaluations, EduWeb peut développer un environnement éducatif dans lequel chaque utilisateur dispose de conditions réelles pour apprendre, participer et réussir.

Le document suivant, **EDU-016 — Architecture de la Qualité Pédagogique**, définira les principes, les référentiels, les mécanismes d’évaluation, les responsabilités, les audits et les processus d’amélioration continue permettant de garantir la qualité des dispositifs éducatifs de l’écosystème EduWeb.
