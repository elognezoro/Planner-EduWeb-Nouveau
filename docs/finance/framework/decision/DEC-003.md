# DEC-003 — Moteur de Règles Métier (Business Rules Engine)

> **Objectif :** Définir l'architecture, le fonctionnement et la gouvernance du moteur de règles métier (Business Rules Engine - BRE) d'EduWeb afin de centraliser, exécuter, tracer et faire évoluer l'ensemble des règles fonctionnelles, réglementaires et institutionnelles utilisées par les applications EduWeb.

# 1. Introduction

Toutes les applications EduWeb appliquent quotidiennement des milliers de règles métier.

Exemples :

- un enseignant ne peut être affecté simultanément à deux classes ;
- une salle de laboratoire ne peut accueillir qu'une discipline compatible ;
- un acte administratif doit être signé par une autorité habilitée ;
- une réservation est refusée si la ressource est indisponible.

Ces règles évoluent régulièrement :

- nouvelles lois ;
- réformes pédagogiques ;
- décisions ministérielles ;
- règlements internes.

Le **Business Rules Engine (BRE)** permet de centraliser ces règles afin d'éviter leur duplication dans les applications.

---

# 2. Pourquoi un moteur de règles métier ?

Sans moteur de règles :

- les règles sont dispersées dans le code ;
- les mises à jour deviennent coûteuses ;
- les incohérences apparaissent rapidement.

Le BRE permet de :

- séparer les règles du code applicatif ;
- faciliter les évolutions ;
- améliorer la traçabilité ;
- garantir une application homogène.

---

# 3. Principes directeurs

Le moteur repose sur les principes suivants :

- **Business Rules First**
- **Configuration over Code**
- **Single Source of Truth**
- **Versioning**
- **Traceability**
- **Explainability**
- **Composable Rules**
- **High Performance**

Les règles doivent être modifiables sans redéployer l'application lorsque cela est possible.

# 5. Typologie des règles

Le moteur distingue plusieurs catégories.

---

## 5.1 Règles réglementaires

Issues :

- des lois ;
- des décrets ;
- des arrêtés ;
- des circulaires.

Exemple :

```text
SI

Volume horaire < minimum réglementaire

ALORS

Refuser la génération.
```

---

## 5.2 Règles pédagogiques

Exemple :

```text
Deux séances de Physique

↓

Éviter deux jours consécutifs.
```

---

## 5.3 Règles organisationnelles

Exemple :

```text
Salle informatique

↓

Réservable uniquement
pour les disciplines numériques.
```

---

## 5.4 Règles administratives

Exemple :

```text
Décision

↓

Visa obligatoire

↓

Signature

↓

Publication
```

---

## 5.5 Règles commerciales

Utilisées notamment dans :

- EduWeb Family ;
- EduWeb Booking.

Exemple :

```text
Abonnement expiré

↓

Services premium indisponibles.
```

---

## 5.6 Règles de sécurité

Exemple :

```text
Utilisateur non autorisé

↓

Refus d'accès.
```

# 8. Mécanisme d'exécution

Chaque règle suit une structure normalisée.

```text
Condition

↓

Évaluation

↓

Décision

↓

Action

↓

Journalisation
```

Exemple :

```text
SI

Salle disponible

ET

Capacité suffisante

ET

Matériel compatible

ALORS

Autoriser l'affectation.
```

---

# 9. Gestion des conflits entre règles

Plusieurs règles peuvent entrer en conflit.

Exemple :

Règle A :

> privilégier les cours du matin.

Règle B :

> limiter les déplacements.

Ces objectifs peuvent être incompatibles.

Le moteur applique alors :

- les priorités ;
- les pondérations ;
- les règles de résolution.

---

## Priorité

Chaque règle possède :

| Niveau | Exemple |
|---------|----------|
| Critique | Loi |
| Haute | Décret |
| Moyenne | Politique académique |
| Faible | Préférence locale |

Les règles critiques prévalent toujours.

---

# 10. Gouvernance

Chaque règle possède :

- un identifiant unique ;
- un propriétaire ;
- une version ;
- une date d'entrée en vigueur ;
- une date de fin de validité (optionnelle) ;
- un statut.

Statuts possibles :

- Brouillon ;
- En validation ;
- Active ;
- Suspendue ;
- Archivée.

Toutes les modifications sont historisées.

# Exemple de règle

## Nom

Validation d'un emploi du temps.

### Conditions

- aucune contrainte dure violée ;
- score global ≥ 90 ;
- robustesse ≥ 85.

### Décision

Autoriser la publication.

Sinon :

Retourner vers le moteur d'optimisation.

# Conclusion

Le **Business Rules Engine (BRE)** constitue le garant de la cohérence fonctionnelle et réglementaire de l'écosystème EduWeb. En séparant les règles métier du code applicatif, il facilite leur gouvernance, leur évolution et leur réutilisation dans l'ensemble des plateformes (Planner, Governance, Booking, Family, Certification, etc.). Associé au moteur décisionnel, aux moteurs d'optimisation et aux composants d'intelligence artificielle, il assure que chaque décision repose sur un référentiel unique, transparent, explicable et conforme aux exigences institutionnelles.
