# DEC-008 — Optimisation des Arbitrages (Decision Arbitration Engine)

> **Objectif :** Définir le moteur d'optimisation des arbitrages d'EduWeb permettant de résoudre les conflits entre objectifs, contraintes et intérêts parfois contradictoires afin de produire les décisions offrant le meilleur compromis global.

# 1. Introduction

Dans un système complexe comme EduWeb, les décisions parfaites existent rarement.

Les décideurs doivent constamment arbitrer entre plusieurs objectifs parfois incompatibles.

Exemples :

- satisfaire les préférences des enseignants ;
- optimiser l'occupation des salles ;
- respecter les contraintes réglementaires ;
- limiter les déplacements ;
- maintenir la robustesse de l'organisation.

L'objectif du moteur n'est pas de rechercher une perfection impossible, mais le **meilleur compromis possible**.

---

# 2. Vision

Le moteur d'arbitrage constitue le cœur du processus décisionnel.

Il permet :

- d'équilibrer plusieurs objectifs ;
- d'expliquer les compromis retenus ;
- d'assurer la cohérence globale ;
- de préserver les priorités institutionnelles.

Il ne remplace jamais la décision humaine.

---

# 3. Objectifs

Le moteur poursuit les objectifs suivants :

- résoudre les conflits entre critères ;
- maximiser la valeur globale ;
- minimiser les effets négatifs ;
- respecter les contraintes obligatoires ;
- proposer plusieurs compromis possibles ;
- expliquer chaque arbitrage.

---

# 4. Principes directeurs

Le moteur applique les principes suivants :

- **Constraint First**
- **Balanced Optimization**
- **Explainable Trade-Off**
- **Fairness**
- **Risk-Aware Arbitration**
- **Human Validation**
- **Adaptive Prioritization**

Les contraintes dites « dures » ne peuvent jamais être sacrifiées.

# 6. Typologie des arbitrages

Le moteur distingue plusieurs catégories d'arbitrages.

---

## 6.1 Pédagogiques

Exemples :

- confort des enseignants ;
- qualité des apprentissages ;
- équilibre des emplois du temps.

---

## 6.2 Organisationnels

Exemples :

- occupation des salles ;
- déplacements ;
- mutualisation des ressources.

---

## 6.3 Réglementaires

Les règles légales sont prioritaires.

Aucun arbitrage ne peut conduire à leur violation.

---

## 6.4 Humains

Exemples :

- équité entre enseignants ;
- équilibre des charges ;
- contraintes individuelles.

---

## 6.5 Économiques

Exemples :

- coût de fonctionnement ;
- optimisation budgétaire ;
- consommation des ressources.

---

## 6.6 Stratégiques

Exemples :

- objectifs ministériels ;
- politique académique ;
- performance globale.

# 9. Méthodes d'optimisation

Le moteur s'appuie sur les composants de la collection **ALG**.

Selon le contexte, il peut utiliser :

- programmation par contraintes (CSP) ;
- optimisation multicritère ;
- recherche tabou ;
- recuit simulé ;
- algorithmes génétiques ;
- Large Neighborhood Search (LNS) ;
- colonies de fourmis ;
- optimisation distribuée ;
- IA hybride.

Le choix de l'algorithme dépend :

- de la taille du problème ;
- du délai disponible ;
- du niveau de qualité attendu.

# 10. Gestion des priorités

Les priorités sont hiérarchisées.

| Niveau | Priorité |
|---------|----------|
| 1 | Contraintes réglementaires |
| 2 | Sécurité |
| 3 | Continuité pédagogique |
| 4 | Robustesse |

| 6 | Préférences individuelles |

Cette hiérarchie peut être adaptée selon le contexte.

---

# 11. Gouvernance

Chaque arbitrage est enregistré avec :

- son identifiant ;
- les critères utilisés ;
- les pondérations ;
- les conflits détectés ;
- les compromis retenus ;
- les explications ;
- la version du moteur.

Toutes les décisions sont auditables.

# Exemple 1 — EduWeb Planner

Deux emplois du temps présentent des avantages différents.

### Option A

- meilleure satisfaction des enseignants.

### Option B

- meilleure utilisation des salles ;
- plus robuste.

Le moteur recommande **l'Option B**, tout en expliquant pourquoi la robustesse est priorisée dans ce contexte.

---

# Exemple 2 — EduWeb Booking

Deux salles sont disponibles.

Salle 1 :

- proche ;
- petite capacité.

Salle 2 :

- plus éloignée ;
- capacité idéale.

Le moteur choisit la seconde afin de garantir le confort et la conformité aux normes d'occupation.

---

# Exemple 3 — EduWeb Governance

Deux circuits administratifs sont possibles.

Le moteur privilégie celui qui :

- réduit les délais ;
- respecte toutes les obligations réglementaires ;
- diminue le nombre d'étapes sans compromettre le contrôle interne.

# Conclusion

Le **Decision Arbitration Engine** est le composant chargé de transformer plusieurs solutions valides en une recommandation équilibrée, conforme et argumentée. En conciliant exigences réglementaires, contraintes opérationnelles, préférences humaines, robustesse organisationnelle et objectifs stratégiques, il permet à EduWeb de proposer des décisions fondées sur le meilleur compromis possible plutôt que sur une optimisation isolée. Associé aux moteurs d'analyse des impacts, d'évaluation des risques, de scoring et de recommandations intelligentes, il constitue un pilier essentiel de la plateforme de **Decision Intelligence** d'EduWeb.
