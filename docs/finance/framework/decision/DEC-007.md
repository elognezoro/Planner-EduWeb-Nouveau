# DEC-007 — Scoring des Décisions (Decision Scoring Engine)

> **Objectif :** Définir le moteur de notation des décisions d'EduWeb permettant d'évaluer objectivement chaque alternative à l'aide d'un score multicritère, explicable, reproductible et configurable, afin de faciliter le classement et la sélection des meilleures décisions.

# 1. Introduction

Une plateforme de **Decision Intelligence** doit être capable de comparer objectivement plusieurs solutions.

Dans EduWeb, chaque décision est évaluée selon de nombreux critères :

- conformité réglementaire ;
- qualité pédagogique ;
- robustesse ;
- impacts ;
- risques ;
- coût ;
- satisfaction des utilisateurs.

Le **Decision Scoring Engine** synthétise ces informations sous la forme d'un score unique facilitant la comparaison des scénarios.

---

# 2. Vision

Le score décisionnel constitue un **indicateur synthétique**, mais ne remplace jamais l'analyse détaillée.

Il doit permettre :

- d'ordonner plusieurs solutions ;
- de justifier leur classement ;
- d'expliquer les écarts ;
- d'aider le décideur.

Le score est donc un **outil d'aide**, et non un mécanisme de décision automatique.

---

# 3. Objectifs

Le moteur poursuit les objectifs suivants :

- normaliser l'évaluation des décisions ;
- agréger des critères hétérogènes ;
- produire un score reproductible ;
- faciliter les arbitrages ;
- améliorer la transparence ;
- alimenter les tableaux de bord décisionnels.

---

# 4. Principes directeurs

Le moteur applique les principes suivants :

- **Multi-Criteria Evaluation**
- **Transparency**
- **Explainability**
- **Configurable Weighting**
- **Fairness**
- **Traceability**
- **Continuous Improvement**

Chaque score doit pouvoir être entièrement recalculé à partir des données disponibles.

# 6. Structure du score

Le score global est composé de plusieurs sous-scores.

| Domaine | Exemple |
|----------|----------|
| Réglementaire | Respect des textes |
| Pédagogique | Qualité de l'organisation |
| Organisationnel | Utilisation des ressources |
| Humain | Satisfaction des acteurs |
| Financier | Coût global |
| Technique | Faisabilité |
| Robustesse | Résistance aux perturbations |
| Risques | Niveau de criticité |

# 8. Pondération dynamique

Les pondérations peuvent varier selon :

- le pays ;
- le ministère ;
- l'académie ;
- l'établissement ;
- le type de décision ;
- le contexte.

### Exemple

| Critère | Lycée | Université |
|----------|------:|-----------:|
| Pédagogie | 35 % | 25 % |
| Ressources | 20 % | 30 % |
| Robustesse | 20 % | 20 % |
| Satisfaction | 15 % | 15 % |
| Coût | 10 % | 10 % |

Cette flexibilité permet d'adapter le moteur à différents contextes institutionnels.

---

# 9. Indice de confiance

En complément du score, le moteur calcule un **indice de confiance**.

Il dépend notamment :

- de la qualité des données ;
- du niveau d'incertitude ;
- du nombre de contraintes satisfaites ;
- de la stabilité des simulations ;
- de la cohérence avec les décisions passées.

### Exemple

| Score | Confiance |
|--------|----------:|
| 96 | 99 % |
| 91 | 95 % |
| 88 | 90 % |
| 83 | 84 % |

Le score et la confiance sont présentés conjointement.

---

# 10. Classement des décisions

Le moteur classe automatiquement les alternatives.

### Exemple

| Rang | Option | Score | Confiance |
|------:|--------|------:|----------:|
| 1 | Option B | 95,2 | 98 % |
| 2 | Option A | 92,7 | 96 % |
| 3 | Option C | 88,9 | 92 % |

Pour chaque option, le système fournit :

- les forces ;
- les faiblesses ;
- les critères pénalisants ;
- les recommandations d'amélioration.

---

# 11. Gouvernance

Chaque score possède :

- un identifiant ;
- une version ;
- les pondérations utilisées ;
- les données d'entrée ;
- les sous-scores ;
- le score global ;
- l'indice de confiance ;
- la date de calcul.

Les calculs sont totalement auditables.

# Exemple 1 — EduWeb Planner

Trois emplois du temps sont générés.

| Option | Score | Confiance |
|---------|------:|----------:|
| A | 91,8 | 96 % |
| B | 95,6 | 99 % |
| C | 89,4 | 91 % |

Le moteur recommande l'**Option B**, qui combine la meilleure conformité réglementaire, une forte robustesse et une excellente répartition des ressources.

---

# Exemple 2 — EduWeb Governance

Deux circuits administratifs sont comparés.

| Option | Score |
|---------|------:|
| Circuit actuel | 78 |
| Circuit optimisé | 93 |

Le nouveau circuit est recommandé en raison de délais plus courts et d'une meilleure conformité.

---

# Exemple 3 — EduWeb Booking

Quatre salles répondent aux critères.

Le moteur attribue un score à chacune en fonction :

- de la capacité ;
- des équipements disponibles ;
- de la proximité ;
- du taux d'occupation ;
- des réservations futures.

La salle présentant le meilleur compromis est proposée en priorité.

# Conclusion

Le **Decision Scoring Engine** constitue le mécanisme central d'évaluation des alternatives au sein de la plateforme de **Decision Intelligence** d'EduWeb. En agrégeant des critères réglementaires, pédagogiques, organisationnels, humains, techniques, financiers et stratégiques dans un score multicritère transparent et explicable, il facilite le classement des scénarios et soutient une prise de décision objective. Couplé aux moteurs d'analyse des impacts, de gestion des risques et de recommandations intelligentes, il garantit des évaluations cohérentes, auditables et adaptables aux différents contextes d'utilisation.
