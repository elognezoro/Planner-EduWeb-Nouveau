# ALG-016 — Optimisation Multi-Agent (Multi-Agent Optimization System)

> **Objectif :** Définir l'architecture multi-agent d'EduWeb Planner permettant à plusieurs agents intelligents de coopérer pour résoudre simultanément les différents sous-problèmes de génération des emplois du temps.

# 1. Introduction

La génération d'un emploi du temps est un problème composé de nombreux sous-problèmes interdépendants :

- enseignants ;
- classes ;
- salles ;
- disciplines ;
- équipements ;
- contraintes réglementaires ;
- préférences locales.

Au lieu de traiter l'ensemble comme un problème monolithique, EduWeb Planner répartit les responsabilités entre plusieurs **agents spécialisés**.

Chaque agent est autonome mais coopère avec les autres afin d'obtenir une solution globale optimale.

---

# 2. Pourquoi une architecture multi-agent ?

Une architecture multi-agent offre plusieurs avantages :

- parallélisation naturelle ;
- modularité ;
- meilleure évolutivité ;
- spécialisation des traitements ;
- adaptation aux très grands établissements.

Elle est particulièrement adaptée aux déploiements nationaux.

---

# 3. Principes directeurs

Le système repose sur les principes suivants :

- **Autonomie**
- **Coopération**
- **Coordination**
- **Négociation**
- **Résilience**
- **Décision distribuée**
- **Explicabilité**

Chaque agent poursuit un objectif local tout en contribuant à l'objectif global.

---

# 4. Architecture générale

```text
                  Orchestrateur

                        │

        ┌───────────────┼────────────────┐

        ▼               ▼                ▼

  Agent Enseignant  Agent Classe   Agent Salle

        │               │                │

        └───────────────┼────────────────┘

                        ▼

              Agent Contraintes

                        ▼

             Agent Optimisation

                        ▼

               Agent Validation

                        ▼

                 Emploi du temps
```

L'orchestrateur supervise la coopération sans imposer toutes les décisions.

---

# 5. Typologie des agents

## Agent Enseignant

Responsabilités :

- disponibilités ;
- charge horaire ;
- préférences ;
- remplacements.

---

## Agent Classe

Responsabilités :

- progression pédagogique ;
- équilibre quotidien ;
- répartition hebdomadaire.

---

## Agent Salle

Responsabilités :

- disponibilité ;
- capacité ;
- équipements ;
- optimisation d'occupation.

---

## Agent Discipline

Responsabilités :

- volumes horaires ;
- séquences pédagogiques ;
- contraintes spécifiques.

---

## Agent Contraintes

Garantit :

- respect des Hard Constraints ;
- cohérence réglementaire.

---

## Agent Optimisation

Recherche :

- meilleure qualité globale ;
- amélioration multicritère.

---

## Agent Validation

Contrôle :

- conformité finale ;
- indicateurs qualité ;
- score global.

# 7. Communication entre agents

Les agents communiquent par messages.

Exemple :

```text
Agent Salle

↓

Laboratoire indisponible

↓

Agent Enseignant

↓

Recherche alternative

↓

Agent Optimisation

↓

Nouvelle proposition
```

Les communications sont asynchrones.

---

# 8. Résolution collaborative

Chaque agent optimise localement.

Ensuite :

```text
Solutions locales

↓

Fusion

↓

Détection conflits

↓

Négociation

↓

Solution commune
```

La coopération est itérative.

---

# 9. Gestion des conflits

Deux agents peuvent proposer des décisions incompatibles.

Exemple :

Agent Enseignant

↓

Préfère mardi matin.

Agent Salle

↓

Salle disponible uniquement mercredi.

↓

Négociation

↓

Compromis optimal.

Les règles de priorité sont définies par le moteur multicritère.

# 11. Cas d'utilisation

## Absence d'un enseignant

L'Agent Enseignant :

- détecte l'absence ;
- consulte les remplaçants.

↓

L'Agent Optimisation adapte uniquement les séances concernées.

---

## Nouvelle salle

L'Agent Salle :

- détecte la nouvelle ressource.

↓

L'Agent Optimisation améliore automatiquement l'occupation.

---

## Réforme pédagogique

L'Agent Discipline :

- met à jour les volumes horaires.

↓

Les autres agents recalculent uniquement les impacts.

---

## Déploiement national

Chaque établissement dispose de ses propres agents locaux.

Un agent régional coordonne ensuite :

- les mutualisations ;
- les statistiques ;
- les comparaisons.

# Conclusion

L'architecture **Multi-Agent** constitue une évolution majeure du moteur algorithmique d'EduWeb Planner. En répartissant les responsabilités entre des agents spécialisés capables de coopérer, négocier et apprendre, elle améliore la modularité, la robustesse et la capacité de montée en charge de la plateforme. Associée aux solveurs CSP, aux métaheuristiques, au Machine Learning et à l'IA explicable, elle prépare EduWeb Planner à gérer efficacement des déploiements de très grande envergure, jusqu'au niveau national et international.
