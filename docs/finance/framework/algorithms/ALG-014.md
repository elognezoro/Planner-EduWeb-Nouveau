# ALG-014 — Apprentissage Automatique des Préférences et Optimisation Adaptative

> **Objectif :** Définir le fonctionnement du moteur d'apprentissage automatique (Machine Learning) d'EduWeb Planner permettant d'apprendre progressivement les préférences des établissements, des enseignants et des gestionnaires afin d'améliorer automatiquement la qualité des emplois du temps générés.

# 1. Introduction

Deux établissements ayant exactement les mêmes contraintes réglementaires peuvent néanmoins produire des emplois du temps très différents.

Pourquoi ?

Parce qu'ils possèdent :

- des habitudes locales ;
- des préférences pédagogiques ;
- une organisation propre ;
- des décisions historiques.

L'objectif du Machine Learning est d'apprendre progressivement ces préférences afin d'améliorer automatiquement les futures générations.

---

# 2. Objectifs

Le moteur doit être capable de :

- apprendre les corrections effectuées par les utilisateurs ;
- détecter les préférences implicites ;
- ajuster automatiquement les paramètres d'optimisation ;
- proposer des solutions de meilleure qualité ;
- réduire les interventions manuelles.

---

# 3. Principes

Le moteur respecte les principes suivants :

- **Learning from Feedback**
- **Human-in-the-Loop**
- **Explainable Learning**
- **Continuous Improvement**
- **Privacy by Design**

L'apprentissage ne modifie jamais directement les contraintes réglementaires.

# 5. Sources d'apprentissage

Le moteur exploite plusieurs sources.

## Historique des emplois du temps

- emplois du temps validés ;
- versions successives ;
- indicateurs de qualité.

---

## Corrections manuelles

Chaque modification est enregistrée.

Exemple :

```text
Déplacement

Mathématiques

↓

Lundi

↓

Mardi
```

Le moteur apprend que cette modification est souvent préférée.

---

## Préférences déclarées

Les utilisateurs peuvent préciser :

- créneaux favoris ;
- salles préférées ;
- contraintes spécifiques.

---

## Données d'exploitation

Le moteur analyse :

- taux de satisfaction ;
- fréquence des modifications ;
- réclamations éventuelles.

---

# 6. Construction des modèles

Plusieurs modèles sont construits.

## Modèle enseignant

Apprend :

- préférences horaires ;
- préférences de salles ;
- habitudes de regroupement.

---

## Modèle établissement

Apprend :

- organisation générale ;
- politique pédagogique ;
- style de planification.

---

## Modèle académique

Analyse les tendances communes à plusieurs établissements.

---

## Modèle national

Permet d'identifier des pratiques récurrentes tout en respectant les spécificités locales.

---

# 7. Personnalisation

Le moteur adapte progressivement :

- les pondérations multicritères ;
- les heuristiques ;
- les stratégies de recherche ;
- les paramètres des métaheuristiques.

Exemple :

Avant apprentissage :

```text
Préférence matin

50 %
```

Après plusieurs années :

```text
Préférence matin

92 %
```

Le moteur ajustera naturellement ses propositions.

---

# 8. Optimisation adaptative

Le moteur combine plusieurs approches.

## Apprentissage supervisé

À partir des décisions validées.

---

## Apprentissage non supervisé

Pour identifier des groupes de comportements similaires.

---

## Apprentissage par renforcement (prévu)

Le moteur recevra une récompense selon la qualité des emplois du temps validés.

---

## Boucle d'amélioration

```text
Nouvelle génération

↓

Validation

↓

Analyse

↓

Apprentissage

↓

Optimisation

↓

Nouvelle génération
```

Cette boucle permet une amélioration continue.

---

# 9. Gouvernance des modèles

Chaque modèle possède :

- un identifiant ;
- une version ;
- une date d'entraînement ;
- un historique des performances.

Les modèles peuvent être :

- réentraînés ;
- restaurés ;
- désactivés.

Toutes les décisions sont journalisées.

# 11. Cas d'utilisation

## Enseignant

Après plusieurs années :

le moteur apprend que Mme Diabaté préfère les cours du matin.

↓

Les prochaines générations privilégient naturellement ces créneaux lorsque cela est compatible avec les contraintes.

---

## Établissement

Le lycée préfère regrouper les travaux pratiques le mercredi.

↓

Le moteur reproduit progressivement cette organisation.

---

## Académie

Une région privilégie les EPS le matin.

↓

Les pondérations régionales sont ajustées.

# Conclusion

Le moteur d'apprentissage automatique d'EduWeb Planner permet à la plateforme de progresser continuellement à partir des décisions humaines et des données historiques. En apprenant les préférences réelles des établissements tout en respectant les contraintes réglementaires, il améliore la qualité des emplois du temps génération après génération. Cette approche d'optimisation adaptative prépare la plateforme à devenir un véritable système intelligent d'aide à la décision, conciliant automatisation, personnalisation et supervision humaine.
