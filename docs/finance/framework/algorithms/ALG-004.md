# 1. Introduction

Le moteur de génération d'EduWeb Planner est fondé sur un **Constraint Satisfaction Problem (CSP)**.

Le problème consiste à trouver une affectation de valeurs à un ensemble de variables tout en satisfaisant simultanément toutes les contraintes.

Cette approche offre :

- une grande expressivité ;
- une excellente modularité ;
- une forte capacité d'évolution ;
- une compatibilité avec les solveurs modernes (Google OR-Tools, Choco Solver, OptaPlanner, etc.).

---

# 2. Pourquoi un CSP ?

Le problème d'emploi du temps possède naturellement les caractéristiques d'un CSP :

- nombreuses variables ;
- domaines finis ;
- contraintes multiples ;
- recherche d'une solution valide.

Contrairement à une simple recherche exhaustive, le CSP élimine très tôt les solutions impossibles grâce à la propagation des contraintes.

---

# 3. Modèle CSP

Le problème est défini par le triplet classique :

\[
CSP = (X, D, C)
\]

où :

- **X** : ensemble des variables ;
- **D** : domaines des variables ;
- **C** : ensemble des contraintes.

---

# 4. Variables

Chaque séance à planifier constitue une variable.

Exemple :

```text
X1 = Cours de Mathématiques 6e A

X2 = Cours de Français 5e C

X3 = TP Physique 1ère C

...
```

Chaque variable doit recevoir une affectation complète.

---

# 5. Domaines

Le domaine représente l'ensemble des affectations possibles.

Exemple :

```text
Créneau

Lundi 08h

Lundi 09h

...

Vendredi 16h
```

Chaque valeur du domaine comprend :

- le créneau ;
- la salle ;
- l'enseignant ;
- les ressources nécessaires.

Le domaine est filtré avant la recherche selon les indisponibilités connues.

---

# 6. Contraintes

Les contraintes sont celles définies dans **ALG-003**.

Le solveur les manipule sous forme de prédicats.

Exemple :

```text
NoTeacherConflict()

NoRoomConflict()

RoomCapacity()

TeacherAvailability()

RequiredHours()
```

Chaque contrainte est indépendante et peut être activée ou désactivée selon les besoins.

---

# 7. Architecture du solveur

```text
Chargement des données
          │
          ▼
Prétraitement des domaines
          │
          ▼
Construction des variables
          │
          ▼
Propagation des contraintes
          │
          ▼
Recherche CSP
          │
          ▼
Solution valide ?
     │             │
    Oui           Non
     │             │
     ▼             ▼
 Validation   Retour arrière
     │
     ▼
Optimisation
     │
     ▼
Publication
```

Le solveur est conçu pour être indépendant des interfaces utilisateur.

---

# 8. Algorithmes de résolution

Le moteur peut combiner plusieurs techniques.

## 8.1 Backtracking

Méthode de base consistant à :

1. affecter une valeur ;
2. vérifier les contraintes ;
3. revenir en arrière en cas d'échec.

Simple mais coûteuse pour les grands problèmes.

---

## 8.2 Forward Checking

Après chaque affectation :

- les domaines des variables restantes sont mis à jour ;
- les valeurs devenues impossibles sont supprimées.

Cette technique réduit fortement l'espace de recherche.

---

## 8.3 Arc Consistency (AC-3)

Le solveur applique l'algorithme AC-3 pour maintenir la cohérence des domaines.

Objectif :

- éliminer les valeurs incompatibles avant la recherche profonde ;
- détecter rapidement les incohérences.

---

## 8.4 MAC (Maintaining Arc Consistency)

Pour les problèmes complexes, la cohérence des arcs est maintenue tout au long de la recherche, améliorant encore les performances.

---

# 9. Propagation des contraintes

Chaque nouvelle affectation déclenche automatiquement une propagation.

Exemple :

```text
Math 6e A

↓

Lundi 08h

↓

Suppression de

- Salle 101
- Enseignant Dupont
- Classe 6e A

pour ce même créneau
```

La propagation réduit progressivement les domaines des variables restantes.

---

# 10. Heuristiques

Afin d'accélérer la résolution, plusieurs heuristiques sont utilisées.

## MRV (Minimum Remaining Values)

Choisir en priorité la variable ayant le moins de valeurs possibles.

---

## Degree Heuristic

En cas d'égalité, sélectionner la variable impliquée dans le plus grand nombre de contraintes.

---

## Least Constraining Value

Choisir la valeur qui restreint le moins les autres variables.

---

## Dynamic Variable Ordering

Réévaluer en permanence l'ordre des variables en fonction de l'état courant de la recherche.

---

# 11. Optimisations

Le solveur intègre plusieurs optimisations.

## Pré-filtrage

Suppression des affectations impossibles avant la résolution.

---

## Décomposition

Découpage du problème par :

- niveau ;
- établissement ;
- bâtiment ;
- filière.

---

## Résolution parallèle

Les sous-problèmes indépendants peuvent être exécutés simultanément sur plusieurs cœurs ou plusieurs nœuds.

---

## Mise en cache

Les sous-solutions fréquemment rencontrées sont mémorisées afin d'éviter des calculs redondants.

---

# 12. Gestion des conflits

Lorsqu'aucune solution n'est trouvée :

1. le solveur identifie les contraintes incompatibles ;
2. il produit un diagnostic ;
3. il propose des pistes de résolution.

Exemple :

```text
Impossible de placer :

Physique 1ère C

Cause :

Aucun laboratoire disponible le mercredi matin.
```

Ces diagnostics facilitent les ajustements par les gestionnaires.

---

# 13. Performance

Objectifs de performance :

| Taille du problème | Temps cible |
|--------------------|------------:|
| 50 séances | < 2 s |
| 500 séances | < 30 s |
| 2 000 séances | < 3 min |
| 10 000 séances | < 10 min |

Les performances dépendent du nombre de contraintes actives et de la qualité des heuristiques.

---

# 14. Validation

Une solution est validée si :

- toutes les variables sont affectées ;
- aucune contrainte dure n'est violée ;
- les indicateurs de qualité sont conformes ;
- le score global dépasse le seuil minimal défini.

Le solveur génère un rapport détaillé comprenant :

- nombre de variables ;
- nombre de contraintes ;
- temps de calcul ;
- nombre de retours arrière ;
- score de qualité.

---

# 15. Évolutions

Les versions futures intégreront :

- solveurs hybrides CSP + Programmation Linéaire ;
- Large Neighborhood Search (LNS) ;
- apprentissage des heuristiques par IA ;
- résolution distribuée sur cluster Kubernetes ;
- adaptation dynamique des stratégies de recherche selon la taille du problème.

# Conclusion

Le solveur CSP constitue le noyau de raisonnement d'EduWeb Planner. Grâce à la combinaison de la propagation des contraintes, des heuristiques de recherche, des techniques de cohérence et des optimisations avancées, il permet de produire efficacement des emplois du temps valides tout en réduisant fortement l'espace de recherche. Cette architecture offre une base robuste sur laquelle pourront se greffer les métaheuristiques et les modules d'intelligence artificielle décrits dans les documents suivants.
