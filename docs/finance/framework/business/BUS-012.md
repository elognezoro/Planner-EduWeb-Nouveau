# 1. Introduction

Les offres commerciales constituent le principal mécanisme de diffusion des produits EduWeb.

Une architecture claire des offres permet :

- une meilleure compréhension par les clients ;
- une simplification des souscriptions ;
- une automatisation des processus commerciaux ;
- une meilleure maîtrise des revenus récurrents.

Cette architecture couvre l'ensemble du cycle de vie des abonnements, depuis la découverte de l'offre jusqu'à son renouvellement ou sa résiliation.

---

# 2. Définition d'une offre

Une offre est un ensemble cohérent de produits, services, fonctionnalités et engagements proposés à une catégorie de clients.

Une offre comprend notamment :

- un public cible ;
- un périmètre fonctionnel ;
- une tarification ;
- des conditions d'utilisation ;
- des niveaux de service (SLA).

---

# 3. Définition d'un abonnement

Un abonnement est un contrat donnant accès à une ou plusieurs offres pour une durée déterminée.

Il est caractérisé par :

- une date de début ;
- une date d'échéance ;
- un niveau de service ;
- des droits d'accès ;
- des modalités de renouvellement.

---

# 4. Vision commerciale EduWeb

EduWeb adopte un modèle **SaaS (Software as a Service)** reposant sur :

- des abonnements récurrents ;
- des offres modulaires ;
- une montée en gamme progressive (Upsell) ;
- une forte fidélisation des utilisateurs ;
- une évolution continue des services.

---

# 5. Objectifs

Cette architecture poursuit les objectifs suivants :

- simplifier l'offre commerciale ;
- favoriser l'adoption des produits ;
- développer les revenus récurrents ;
- améliorer la fidélisation ;
- faciliter les renouvellements ;
- soutenir l'expansion internationale.

---

# 6. Principes directeurs

Les offres EduWeb respectent les principes suivants :

- Simplicité ;
- Transparence tarifaire ;
- Modularité ;
- Évolutivité ;
- Paiement sécurisé ;
- Personnalisation ;
- Conformité réglementaire.

# 11. Architecture des abonnements

Les abonnements sont organisés en plusieurs niveaux.

| Niveau | Public cible | Caractéristiques |
|---------|--------------|------------------|
| Découverte | Nouveaux utilisateurs | Fonctionnalités essentielles |
| Standard | Établissements | Services principaux |
| Professionnel | Grandes structures | Services avancés |
| Entreprise | Institutions nationales | Services complets |
| Partenaire | Organismes partenaires | Fonctionnalités dédiées |

Chaque niveau peut être enrichi par des options complémentaires.

# 13. Gestion des licences

Les licences sont attribuées selon :

- le nombre d'établissements ;
- le nombre d'utilisateurs ;
- le nombre de modules ;
- les droits d'administration.

Les licences peuvent être :

- individuelles ;
- institutionnelles ;
- nationales.

---

# 14. Gestion des options

Des options peuvent être ajoutées :

- intelligence artificielle avancée ;
- stockage supplémentaire ;
- assistance premium ;
- intégrations spécifiques ;
- développements personnalisés.

---

# 15. Architecture tarifaire

Les tarifs reposent sur plusieurs critères.

## Abonnement annuel

Formule privilégiée pour les établissements.

---

## Abonnement mensuel

Adapté aux besoins ponctuels.

---

## Tarification institutionnelle

Destinée aux ministères et grandes organisations.

---

## Tarification personnalisée

Réservée aux projets spécifiques nécessitant un accompagnement particulier.

---

# 16. Modes de paiement

Les moyens de paiement supportés incluent :

- Mobile Money ;
- cartes bancaires ;
- virements bancaires ;
- paiement institutionnel ;
- paiement par bon de commande.

Les transactions sont sécurisées et tracées.

---

# 17. Promotions et campagnes

Les campagnes commerciales peuvent proposer :

- essais gratuits ;
- remises de lancement ;
- offres de fidélité ;
- parrainage ;
- campagnes saisonnières.

Chaque campagne est limitée dans le temps et fait l'objet d'un suivi.

---

# 18. Renouvellements

Le renouvellement peut être :

- automatique ;
- manuel ;
- assisté.

Des rappels sont envoyés avant l'échéance.

Les historiques sont conservés pour l'analyse de la fidélisation.

---

# 19. Résiliation

La résiliation respecte les principes suivants :

- transparence ;
- conservation des données selon les politiques applicables ;
- possibilité d'export des données ;
- clôture des accès ;
- enquête de satisfaction.

---

# 20. Gouvernance commerciale

Chaque offre dispose :

- d'un responsable commercial ;
- d'un Product Owner ;
- d'indicateurs de performance ;
- d'une politique tarifaire ;
- d'une feuille de route.

Les évolutions sont validées par le Comité Produit et la Direction Générale.

# 27. Conclusion

L'**Architecture des offres et abonnements** transforme le portefeuille de produits EduWeb en une offre commerciale cohérente, évolutive et adaptée aux différents profils d'utilisateurs.

En structurant les niveaux d'abonnement, les modèles de licences, les règles tarifaires, les mécanismes de renouvellement et les services complémentaires, elle favorise une croissance durable des revenus récurrents tout en améliorant la satisfaction et la fidélisation des clients.

Cette architecture constitue également le socle de la stratégie commerciale d'EduWeb, en facilitant la personnalisation des offres, l'automatisation des processus de souscription et l'adaptation aux besoins des établissements, des administrations et des partenaires.

Le document suivant, **BUS-013 — Architecture des partenaires**, décrira l'écosystème de partenaires d'EduWeb, les modèles de collaboration, les responsabilités, les flux d'échange, les mécanismes de gouvernance et les stratégies de co-création de valeur.
